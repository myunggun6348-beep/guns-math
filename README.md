# GUN’s MATH

고등학교 수학에서 말로 설명하기 어려운 개념을 학생이 직접 움직여 볼 수 있게 만든 웹 자료실.
자료실 · 질문 · 공지, 세 게시판이 각각 독립된 페이지로 되어 있다.

## 구조

```
index.html                 랜딩페이지 (소개 + 탭 세 개 + 공지 한 줄)
library.html                자료실 — 과목별·검색, 자료 17개
map.html                    개념 지도 — 개념 19개의 선후 관계, 자료로 가는 또 다른 입구
ask.html                    질문 — 학생이 묻고 선생님이 답하는 게시판
assets/demos.js            자료 목록 (DEMOS) + 푸터 요약 줄 — 네 페이지가 함께 씁니다
assets/style.css           사이트 전체 공통 스타일
assets/state.js            수업용 링크 (조작값 ↔ 주소) — 모든 자료가 함께 씁니다
assets/og.png              카톡·문자 공유 미리보기 이미지 (1200×630)
assets/og-source.html      위 이미지를 다시 만들 때 쓰는 원본
assets/vendor/             three.js · 폰트 (인터넷 없이도 열리도록 함께 보관)
폰으로 보기.bat            ← 더블클릭하면 홈페이지가 켜집니다 (아래 "내 컴퓨터·폰에서 보기")
serve.js                   위 .bat 이 실행하는 것 — 폰에서 볼 주소도 찾아서 알려 줍니다
```

세 페이지 모두 같은 상단 내비게이션과 푸터를 쓴다. 로고를 누르면 `index.html`로,
"직접 보는 수학"은 `library.html`로, "질문"은 `ask.html`로, "공지"는 `index.html#notice`로 간다.

960px 이하 폭(폰·태블릿)에서는 "공지"·"질문" 링크가 오른쪽 위 햄버거 버튼 안으로 들어간다.
자바스크립트 없이 체크박스만으로 여닫히므로(`style.css`의 `.nav-toggle-*`), 새 페이지를
만들 때도 헤더 블록을 그대로 복사하면 폰 메뉴가 함께 따라온다.
햄버거의 누르는 영역은 44×44px(권장 최소치)이고, 막대 3개는 20px 그대로다 —
`.nav-toggle`의 `margin-right: -6px`가 넓어진 만큼을 되돌려 아이콘 위치를 유지한다.
지금 있는 페이지의 링크/버튼에는 `aria-current="page"`를 달아 옅은 회색으로 표시한다
(예: `library.html`에서는 "직접 보는 수학" 버튼이, `ask.html`에서는 "질문" 링크가).
### 홈 가운데 — 탭 세 개 (`index.html`)

예전에는 이 자리에 공지 목록이 통째로 있었다. 홈에 처음 온 학생에게 가장 먼저
보여야 할 것이 시험 범위는 아니라고 보고, **자료로 들어가는 문 세 개**로 바꿨다.

| 탭 | 보여 주는 것 | 어디서 오나 |
| --- | --- | --- |
| 새로 올린 자료 | 카드 3개 | `DEMOS` 배열의 **맨 끝 세 개** |
| 오늘의 한 장면 | 자료 하나가 홈에서 그대로 돌아감 | 날짜로 고름 (3D 자료는 제외) |
| 과목별로 | 과목 칩 6개 + 개수 | `SUBJECTS` |

셋 다 `assets/demos.js` 에서 저절로 만들어진다. **자료를 추가하는 것 말고는
손댈 것이 없다.** 주소 뒤에 `#today` / `#subject` 를 붙이면 그 탭이 열린 채로
뜨므로, 특정 탭을 링크로 보낼 수도 있다.

**'오늘의 한 장면'에서 알아 둘 것 두 가지.**

- 자료 페이지가 `height: calc(100vh - 57px)` 로 창을 꽉 채우게 되어 있다.
  그래서 안쪽 내용을 재서 창 높이를 맞추려 해도 준 만큼만 늘어난다(순환).
  높이는 `style.css` 의 `.today-frame` 한 곳에서 정한다 (`min(560px, 72vh)`).
- **폰(768px 미만)에서는 싣지 않고 그림 카드만 보여 준다.** 폰 너비에서는
  자료 속이 1,400px 이 넘어서, 작은 창에 넣으면 창 안에서 또 스크롤이 생기고
  손가락이 어느 쪽을 미는지 알 수 없게 된다. 자료 페이지 자체가 화면 전체를
  쓰도록 만들어져 있으니 눌러서 그리로 보내는 편이 낫다.

홈 안에 실릴 때는 자료 페이지 맨 위의 '← 자료실' 줄을 숨긴다. 홈이 iframe 안
문서에 `embedded` 표시를 달고, `style.css` 의 `.embedded .demo-bar` 가 숨긴다.
자료 페이지를 직접 열면 그 표시가 없으니 평소대로 보인다.

### 공지 — 접히는 한 줄

`index.html` 의 `<details class="notice-strip">`. 맨 위 한 개만 보이고 ＋ 를 누르면
나머지가 펼쳐진다. `NOTICES` 배열이 비면 줄 자체가 사라지므로 빈 게시판이 남지
않는다. 다른 페이지의 "공지" 메뉴(`index.html#notice`)로 들어오면 펼친 채로 뜬다.

### 개념 지도 (`map.html`)

같은 자료 17개로 들어가는 **두 번째 입구**다. 자료실이 "무엇이 있나"라면
개념 지도는 "지금 배우는 게 어디서 왔나"에 답한다.

고칠 곳은 파일 안 `<script>` 세 군데뿐이다:

- `NODES` — 개념 19개. 각 개념의 `demos` 배열에 자료를 한 줄씩 매단다
- `LAYERS` — 배우는 순서대로 쌓은 층. 여기 적힌 순서가 화면 순서다
- `EDGES` — `[먼저, 나중]`. "이게 있어야 저게 된다"

**개념 상자의 좌표는 어디에도 적혀 있지 않다.** 배치는 CSS(flex)가 하고,
script 는 그려진 자리를 재서 선만 얹는다 — 그래서 폰이든 데스크톱이든
저절로 맞는다. 좌표를 손으로 박는 순간 좁은 화면에서 반드시 깨진다.

같은 줄에 나란히 놓인 두 개념(예: 평면벡터 → 공간도형)은 위아래로 이으면
선이 거꾸로 올라가므로, 옆으로 잇고 아래로 부풀린다.

`map.html?n=trig` 처럼 개념을 지정해 링크를 보낼 수 있다 (수업 중에 쓰기 좋다).

### 제목 단계 (h1 → h2 → h3)

페이지마다 `h1`은 하나뿐이고, 그 아래로 단계를 건너뛰지 않는다. 검색 노출과
화면낭독기가 이걸 보고 페이지 제목을 잡으므로, 새 페이지를 만들 때도 지켜 주세요.

| 페이지 | h1 | h2 | h3 |
|---|---|---|---|
| `index.html` | GUN's MATH (히어로) | 공지 | 공지 한 건씩 |
| `library.html` | 직접 보는 수학 | 과목 이름 (`.grid-head`) | 자료 카드 제목 |
| `map.html` | 개념 지도 | 층 이름 · 고른 개념 이름 | 먼저/이어지는/자료 |
| `ask.html` | 선생님한테 직접 물어보기 | 받은 질문과 답 | 질문 한 건씩 |

푸터의 Menu 는 `h3` 다 — `h4` 로 두면 개념 지도에서 개념을 고르기 전에
h2 다음이 바로 h4 가 되어 단계가 건너뛰어진다.

`library.html`의 과목 이름은 `render()` 안에서 `<h2>`로 만든다. 태그를 바꾸면
`style.css`의 `.grid-head h2` 선택자도 같이 고쳐야 글자 크기가 유지된다.

### '맨 위로' 단추 (`library.html`)

자료실은 폰에서 8,000px 가까이 되어, 아래쪽 과목을 보다가 다른 과목으로 옮기려면
과목 칩이 있는 맨 위까지 되돌아가야 했다. 오른쪽 아래 떠 있는 `.to-top` 단추가
그 역할을 하고, 960px 이하에서 한 화면(600px)쯤 내려간 뒤부터 나타난다.
(칩 줄 자체를 고정하려면 `.toolbar`를 sticky 로 만들어야 하는데, 폰에서는
칩 + 검색이 219px 이라 화면을 너무 많이 가려서 이 방식을 골랐다.)

단추에 흰 테두리 2px 이 둘러져 있는데, 푸터가 검은 색면이라 그렇다. 자세한
이유는 아래 [푸터](#푸터) 참고.

### 인터넷 연결이 필요 없습니다

three.js 와 글꼴을 사이트 안에 같이 넣어 두었으므로, 학교 방화벽이 외부 CDN

### 수업용 링크

자료를 열고 슬라이더를 원하는 값에 맞추면 **주소가 그 상태로 바뀝니다.**
오른쪽 위 **"링크 복사"** 를 눌러 그대로 보내면, 받은 사람도 같은 화면으로 열립니다.

```
demos/conic-sections.html?theta=75&height=0.6     θ=75° → 쌍곡선
demos/riemann.html?n=40&mode=right                직사각형 40개, 오른쪽 끝 값
```

주소에는 **기본값과 다른 것만** 담기므로 짧게 유지됩니다.
`assets/state.js` 가 전 자료에서 공통으로 처리하니 자료를 새로 만들어도
맨 아래 `<script src="../assets/state.js"></script>` 한 줄이면 됩니다.
(몬티 홀처럼 슬라이더가 없는 자료에서는 버튼이 생기지 않습니다)

데모 한 개 = HTML 파일 한 개. 서로 영향을 주지 않으므로 마음 편히 추가·수정할 수 있다.

## 글 올리는 법

- **자료** — `assets/demos.js` 의 `DEMOS` 배열 **맨 아래에** 추가합니다.
  비슷한 항목을 복사해서 고치면 됩니다. 홈과 자료실이 이 한 파일을 함께 봅니다.
  - `fig` : 카드에 들어가는 작은 그림 (SVG)
  - `use` : 카드에 보이는 "이럴 때" 한 줄 — 수업에서 언제 꺼내 쓰는지
  - `desc` : 화면에는 안 나오지만 **검색에는 걸리는** 설명문 (`keywords` 와 같은 역할)
  - `d3: true` : 3D 자료에 붙는 검은 **3D** 배지. 홈의 '오늘의 한 장면' 에서는 빠집니다
    (홈에서 three.js 까지 받아 오면 폰에서 느리기 때문)
  - 과목 색과 목차는 `subject` 값을 보고 자동으로 붙습니다 (색은 `style.css` 의 `--sub-*`)
- **질문·답변** — `ask.html` 아래쪽 `QNA` 배열 (최신 글을 맨 앞에)
- **공지** — `index.html` 아래쪽 `NOTICES` 배열 (최신 글을 맨 앞에).
  홈에서는 맨 앞 한 개만 한 줄로 보이고 나머지는 ＋ 안에 접힙니다

한 줄 추가하고 파일을 올리면 화면에 그대로 반영된다.

과목이 하나 늘거나 이름이 바뀌면 `assets/demos.js` 의 `SUBJECTS` 만 고치면 된다.
(예전에는 푸터에도 과목 6개를 나열해 세 파일을 같이 고쳐야 했는데, 푸터에서
과목 목록을 빼면서 그 부담이 없어졌다 — 아래 "푸터" 참고)

### 푸터

네 페이지 모두 같은 푸터를 쓴다. **2단**이다:

| 왼쪽 | 오른쪽 |
| --- | --- |
| 이름 · 한 줄 소개 · 자료 요약 | Menu (링크 5개, 가로 한 줄) |

검은 색면(`--inverse-canvas`) 위에 흰 글씨다.

푸터는 '끝났다'는 표시지 두 번째 홈페이지가 아니다. 예전에는 과목 6개를 다시
나열하느라 홈 전체 높이의 31%(577px)를 차지했고, 그중 192px 은 위·아래
여백(96px 두 개)으로 그냥 비어 있었다. 지금은 데스크톱 **250px(16%)** 다.
링크를 다시 늘리고 싶어질 때 이 숫자를 기억해 두면 좋다.

**줄여 온 순서** — 한 번에 줄인 게 아니라 세 번에 걸쳐 줄였고, 매번 원인이
달랐다. 같은 실수를 반복하지 않으려고 적어 둔다.

1. 3단(브랜드 / Menu / Contact) → Contact 칸에 항목이 **하나뿐**이라 오른쪽이
   허전하게 비었다. 링크를 한 목록으로 합쳐 2단으로.
2. 2단인데도 높았다 → 링크 5개가 **세로로 쌓여** 오른쪽이 5줄인데 왼쪽은
   2줄에서 끝났다. 칸 높이는 둘 중 긴 쪽을 따라가므로 왼쪽 아래에 200px 넘는
   빈자리가 생긴 것. 링크를 가로 한 줄로 눕혀서(`.footer ul` 이 flex) 해결.
3. 그러고 나니 왼쪽에 한 줄이 더 들어갈 자리가 생겼다 → **자료 요약**을 넣었다.

**자료 요약 줄**(`자료 17개 · 마지막 업데이트 2026-08-06`)은 손으로 적지 않는다.
`assets/demos.js` 맨 아래가 채운다 — 개수는 `DEMOS` 를 세고, 날짜는 그 파일이
고쳐진 날을 서버에 물어본다. 자료를 추가하면 그 파일이 바뀌므로 **네 페이지의
숫자와 날짜가 한꺼번에** 따라온다. 푸터에 `<span id="footerStat">` 이 있는
페이지에서만 동작하고, 없으면 아무 일도 하지 않는다.

> 그래서 `ask.html` 과 `map.html` 도 `assets/demos.js` 를 읽는다. 그 두 페이지는
> 자료 목록 자체는 안 쓰지만, 이 요약 줄 때문에 필요하다.

**왜 검은 색면인가.** 흰 바탕에 실선 한 줄만 그어 두니 '아직 본문인가' 싶게
이어져 보였다. 색이 바뀌면 줄 하나 없이도 여기가 끝인 게 보여서, `border-top`
은 지웠다. 대신 어두운 바탕에서 안 보이게 되는 것 세 가지를 함께 뒤집어 뒀다.
이 셋은 색을 다시 바꿀 때도 같이 따라다녀야 한다.

| 원래 | 검은 바탕에서 생기는 문제 | 바꾼 것 |
| --- | --- | --- |
| `.caption` `rgba(0,0,0,.58)` | 검정 위 검정 — 안 보임 | `.footer .caption` 흰색 55% |
| `:focus-visible` 검정 테두리 | 키보드로 다닐 때 지금 어디인지 안 보임 | `.footer :focus-visible` 흰색 |
| `.to-top` 검은 원 단추 | 끝까지 내리면 배경에 묻힘 | 흰 테두리 2px (흰 바탕에서는 티가 안 남) |

**폰(390px)에서는** 두 칸이 세로로 쌓이고 링크 줄이 두 줄로 꺾여서 394px 이다.
가로 스크롤은 생기지 않는다(링크 줄 오른쪽 끝 284px < 390px). 메뉴를 더 늘리면
세 줄이 되니 그때 다시 잰다.

`og:image` · `og:url` 은 이미 실제 주소(`https://guns-math.vercel.app`)로

### 질문을 실제로 받으려면

이 사이트는 서버 없이 파일만 올라가는 방식이라, 학생이 쓴 글이 사이트에 저장되지는 않는다.
구글 폼(무료)을 하나 만들어 "질문 남기기" 버튼에 연결하면 답변이 선생님 구글 시트로 모인다.
그중 공유할 만한 것을 `QNA` 배열에 옮겨 적으면 페이지에 답변이 쌓인다.

색을 바꾸고 싶으면 `assets/style.css` 맨 위 `:root` 의 값만 고치면 사이트 전체가 함께 바뀐다.

## 내 컴퓨터·폰에서 보기

**`폰으로 보기.bat` 을 더블클릭**하면 끝난다. 검은 창이 뜨면서 주소를 알려 준다.
그 창을 닫으면 서버가 꺼진다. (창은 켜 둔 채로 두면 된다)

- 이 컴퓨터에서는 `http://localhost:5173`
- 폰에서는 창에 찍히는 `http://192.168.…:5173` — **폰이 같은 와이파이에 있어야 한다**

폰용 주소는 공유기가 그때그때 정해 주므로 **켤 때마다 달라질 수 있다.** 외우지 말고
창에 찍히는 것을 그대로 보고 치면 된다 (`serve.js`가 매번 다시 찾아 준다).

3D 자료는 모듈을 불러오기 때문에, 파일을 그냥 더블클릭하는 방식(`file://`)으로는
열리지 않는다. 위 방법으로 열어야 하는 이유다.

명령창에 직접 치고 싶으면 이 폴더에서 `node serve.js`.

### 폰에서 안 열릴 때

1. 폰이 PC와 **같은 와이파이**인지 (폰의 데이터를 끄고 다시 해 보면 확실하다)
2. Windows 방화벽 창이 떴다면 '개인 네트워크'에 체크하고 [액세스 허용]
3. 그래도 안 되면 공유기의 '단말 간 차단(AP isolation)' 설정 때문일 수 있다 —
   이때는 아래 Vercel 로 올리는 편이 빠르다

## 인터넷에 올리기 (Vercel, 무료)

올리고 나면 PC 를 켜 둘 필요도, 같은 와이파이일 필요도 없어진다.
학생은 링크만 누르면 되고, 폰에서도 그냥 열린다.

이 폴더는 이미 git 저장소이고 첫 커밋이 들어 있다 (`git log` 로 확인).

1. **GitHub 에 저장소 만들고 올리기** — `gh repo create` 로 한 번에 된다.
   **비공개(Private)로 둬도 Vercel 은 배포한다.** (GitHub Pages 무료 계정은
   공개여야 하지만, Vercel 은 그 제약이 없다)
2. **vercel.com** → GitHub 계정으로 로그인 → **Add New → Project** →
   이 저장소 **Import** → 설정 건드릴 것 없이 **Deploy**
   (빌드 도구를 안 쓰는 정적 사이트라 Vercel 이 알아서 알아본다)
3. 1 분쯤 뒤 `https://….vercel.app` 주소가 나온다. 이걸 학생에게 준다

### 그 다음부터는 웹에서만 작업하면 된다

`github.com` 에서 파일을 열고 연필 아이콘으로 고친 뒤 **Commit changes** 를 누르면,
Vercel 이 알아서 다시 배포한다. 폰에서 새로고침하면 바뀌어 있다.
컴퓨터에 파일을 두고 명령어를 칠 필요가 없다.

### 올린 뒤 한 번만 할 일

네 페이지의 `og:image` 가 상대경로(`assets/og.png`)로 되어 있다. 카톡 미리보기가
확실히 뜨게 하려면 실제 주소(`https://….vercel.app/assets/og.png`)로 바꿔 두면 좋다.
`og:url` 도 같이 넣어 두면 더 확실하다.

## 새 자료 추가 순서

1. `demos/` 안에 새 HTML 파일을 만든다 (`projection.html`을 복사해서 시작하면 빠름,
   맨 아래 `<script src="../assets/state.js"></script>` 도 그대로 두면 수업용 링크가 함께 딸려 온다)
2. **`assets/demos.js`** 의 `DEMOS` 배열 **맨 아래**에 항목을 추가하고 `ready: true` 로 둔다
   (검색이 되도록 `keywords` 에 관련 용어를 넣어 둘 것)

그러면 이 셋이 저절로 따라온다:

- **자료실** — 과목별로 알아서 제자리에 들어간다. `SUBJECTS` 에 적은 과목 순서로
  묶으므로, 배열의 어디에 넣든 상관없다. (예전에는 배열을 훑다가 과목이 바뀔 때마다
  제목을 만들었다. 그래서 같은 과목을 떨어뜨려 놓으면 제목이 두 번 생기고 같은 id 가
  두 개가 되어 바로가기가 엉켰다. 지금은 그 제약이 없다)
- **홈 '새로 올린 자료'** — 배열 맨 끝 세 개를 보여 주므로, 아래에 붙이면 바로 올라온다
- **네 페이지 푸터의 '자료 N개 · 마지막 업데이트'** — 개수는 배열을 세고, 날짜는
  `assets/demos.js` 가 고쳐진 날을 서버에서 읽어 온다. 손으로 적는 곳이 아니다
