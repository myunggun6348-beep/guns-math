# 수학을 보다

개인 계정으로 로그인해 맞춤 수학 문제·오답·복습·주간 성과를 이어가는 학습 홈페이지. 공개 수학 자료와 가입 없는 체험도 제공합니다.
가입 후 선택적으로 약 5분의 학습 진단을 시작할 수 있습니다. 기본 개념 5문항(오지선다·주관식)을 확인하며 미학습을 오답과 구분합니다. 결과는 과목별 진단으로 계정에 별도 보관하고 오늘의 점수·오답 기록에 집계하지 않습니다. 일반 학습 기록이 없는 개념의 진단 결과를 맞춤 문제 구성에 참고합니다. 홈의 ‘나의 학습 진단’에서 기존 학생도 시작하거나 재진단할 수 있습니다.
선생님 방의 개인 학습 현황에서는 학생별 ‘학습 진단 결과’를 펼쳐 과목별 최근 진단·개념별 정답/재확인/미학습을 확인하고 개념 지도와 관련 기출로 연결할 수 있습니다. 완료 후 계정에 동기화된 결과만 표시하며, 일반 학습 점수와는 별도입니다.
‘진단 이후 학습 변화’에서는 같은 학년·과목·개념의 진단과 후속 학습을 막대로 비교합니다. 기능 적용 후 보관된 개념별 최근 50회에서 문항별 첫 기록의 힌트 없는 풀이만 비교하고 힌트 사용·오답 재풀이는 별도 표시합니다. 과거 누적 기록으로 변화량을 추정하지 않으며, 재진단 시 최근 진단 이후부터 비교합니다.
진단과 후속 학습에 맞춘 ‘다음 추천 학습’도 제공합니다. 예정된 오답 복습, 미학습 개념 설명, 기초·표준·도전 1문항 중 다음 활동을 안내하며 추천 이유를 학생과 선생님에게 함께 보여줍니다. 추천 문제의 힌트·태블릿 풀이·이어하기를 지원하고 오늘의 5문제 점수는 별도로 보존합니다.
학생 홈과 선생님 화면의 ‘앞으로 7일 학습 계획’은 현재 선택 과목의 진단·추천·오답 복습 일정을 하루별 활동으로 연결합니다. 한국 시간 기준으로 매번 갱신하며 기존 복습 날짜와 점수는 유지합니다. 복습이 많은 날에는 먼저 최대 2문제를 권하고, 완료 여부를 임의로 표시하거나 알림을 보내지 않습니다.
각 학습 화면은 독립되어 있고, 상단 메뉴와 푸터를 공유한다.

로그인한 학생의 홈에는 ‘오늘의 학습’ 진행률을 표시합니다. 한국 날짜·학년·과목별로 예정된 오답 최대 2문제, 맞춤 5문제, 추천 개념 1문항을 묶고 그날 새로 생긴 오답으로 분량을 늘리지 않습니다. 실제 제출한 활동은 정답 여부와 구분해 완료 표시하며, 결과에서 다음 활동으로 이어집니다. 모두 마치면 다시 확인할 개념과 다음 예정 복습 날짜를 안내합니다. 학생 홈의 7일 계획에서 오늘 항목도 이 활동으로 연결합니다.
하루 활동 묶음과 최초 제출 결과는 계정에 동기화하고 최근 30개 묶음을 보관합니다. 두 기기에서 서로 다른 계획을 만들었으면 먼저 만든 계획을 기준으로 같은 활동의 결과를 합칩니다. 필기·입력 중인 임시 풀이는 기존처럼 해당 기기에 보관하며, 기존 점수·오답의 복습 일정은 유지합니다. 가입 없는 체험 학습도 그대로 이용할 수 있습니다.
선택한 과목의 오늘 활동을 모두 마치면 결과 화면과 홈에 ‘오늘의 성과’ 카드를 보여줍니다. 완료한 활동 수·제출 문항 수·정답 문항 수, 힌트 사용·재확인 개념·다음 예정 복습을 간단히 정리하고 활동별 내역은 펼쳐볼 수 있습니다. 오늘 정한 활동별 첫 제출만 합산하며 힌트를 사용한 확인 문제의 정답도 포함합니다. 삭제되어 제외된 문제는 제출/정답 수에 더하지 않습니다. 카드 표시는 기존 학습 기록과 점수를 변경하지 않습니다.
로그인 홈은 학습 전·진행 중·완료 후에 따라 주요 카드 하나를 바꿔 보여줍니다. 시작 전에는 첫 활동과 오늘 분량, 진행 중에는 이어하기/다음 활동과 남은 학습, 완료 후에는 성과 카드가 중심입니다. 평균·연속 학습·오답 수·주간 성과는 ‘학습 기록 보기’에서 펼쳐 확인합니다. 저장된 추가 풀이가 있으면 완료 후에도 이어하기를 우선하고 다른 과목의 풀이와 현재 과목 진행률을 섞지 않습니다. 전체 메뉴는 아래에서 계속 열린 상태로 제공합니다.
선생님 방에서도 ‘오늘의 하루 학습’을 펼쳐 학생의 과목별 완료율·남은 활동·제출 결과·힌트·다시 확인할 개념을 볼 수 있습니다. 하루 활동 완료/남은 활동/오늘 기록 없음 필터를 제공하며, 오늘의 5문제 점수와 구분합니다. 여러 과목을 시작했으면 모두 마쳐야 하루 완료로 표시하고, 오늘 동기화된 계획이 없다는 이유만으로 미학습으로 판단하지 않습니다. 읽기 전용이며 학생의 답·필기·인증 정보를 표시하지 않습니다.

**"직접 보는 수학"과 "자료실"은 다른 것이다.** 앞엣것(`library.html`)은 화면에서
직접 움직여 보는 것, 뒤엣것(`files.html`)은 내려받아 인쇄하는 것. 이름이 헷갈리기
쉬우니 새 항목을 어디에 넣을지 먼저 정하고 손대는 편이 좋다.

### 도구 (`scripts/`)

**기출 목록 새로 받기** — 새 모의고사가 나왔을 때. `기출 목록 새로 받기.bat` 을
더블클릭하면 EBSi 를 다시 훑어 `assets/exam-catalog.json` 을 새로 쓴다. 파일이
실제로 열리는지(크기·형식·지문)까지 확인하느라 몇 분 걸린다. 목록만 빨리 받으려면:

```
node scripts\update-exam-catalog.js --skip-verify
node scripts\update-exam-catalog.js --years 2024-2026
```

> `scripts/update-exam-catalog.py` 는 같은 일을 하는 예전 판이다. **이 컴퓨터에는
> 파이썬이 없어서 돌지 않으므로** 위 `.js`(또는 `.bat`)를 쓸 것. 둘은 같은 결과를
> 낸다 — 옮긴 뒤 39회·파일 219개의 주소와 지문(sha256)이 하나도 다르지 않은 것을
> 확인했다.

### 학습과 분석

홈은 개인 로그인 중심입니다. 로그인 전에는 로그인·회원가입·계정 찾기를 표시하고 공개 자료와 체험 학습을 유지합니다. 로그인 후에는 자신의 학년·과목, 이어하기, 맞춤 문제, 오답과 주간 성과를 표시합니다. 반 입력/표시는 개인 홈에서 제거하고 기존 반 값은 저장된 프로필과 관리 화면의 ‘기존 반 정보로 보기’에 보존합니다. 관리 화면도 개인 학습 현황을 기본으로 보여줍니다.

로그아웃하거나 세션이 만료되면 계정 기록을 해당 기기의 계정별 보관본에 남기고 이전 체험 기록으로 전환합니다. 재로그인하면 보관된 필기와 미전송 기록을 복원해 서버 기록과 병합합니다. 체험 기록은 `math-student-guest-data-v1`, 마지막 로그인 아이디는 `math-student-last-id-v1`로 보관합니다. 기록 분리에 실패한 경우 이전 계정 기록의 읽기/덮어쓰기를 막고 오류를 안내합니다. 새 가입 설정은 계정 준비 후 저장해 체험 프로필을 가입자 이름으로 덮어쓰지 않습니다. 체험 방문은 탭의 명시적 선택(`math-home-explore`)으로 개인 체험 홈을 엽니다.

학생 홈의 ‘주간 복습 성과 보기’에서 한국 시간 기준 오늘을 포함한 최근 7개 날짜의 정답 확인·최종 완료와 개념별 성과를 확인합니다. 선생님 방 학생별 같은 제목의 분석에서도 계정에 동기화된 주간 성과와 오늘 복습/전체 미완료 개수를 볼 수 있습니다. 두 화면은 같은 `StudyState.reviewSummary` 집계 기준을 사용하며 현재 보관 중인 오답별 마지막 복습만 셉니다. 삭제·재오답 노트는 성과에서 제외하고 기록이 없으면 0으로 표시합니다. 비회원 기록과 동기화하지 않은 기기의 기록은 선생님 집계에 포함되지 않습니다.

오답 재풀이를 맞히면 해당 개념의 오답을 다시 맞혔다는 안내와 복습 확인 단계/다음 일정을 표시합니다. 마지막 4번째 확인까지 마친 경우만 복습 완료로 안내하며 예정일 전 정답은 단계를 유지한다고 표시합니다. 학생이 ‘복습 목록으로’를 누를 때까지 결과를 유지합니다. 홈에는 최근 7일 동안 보관 중인 오답의 마지막 복습 정답 확인을 문제별 한 번 집계해 개념과 최종 완료 개수를 보여줍니다. 다시 틀려 단계가 초기화되거나 삭제한 노트는 제외합니다. 모든 과거 복습 횟수나 개념 전체의 숙달도를 뜻하지 않습니다.

홈 학습 기록은 ‘오늘 복습할 문제’(복습 예정 시각이 됐거나 지난 문제와 아직 일정이 없는 새 오답)와 ‘전체 미완료 오답’(미래 복습 예정 포함)을 별도로 표시합니다. 완료한 오답은 두 개수에서 제외합니다. PC는 기록 카드 네 개를 한 줄로, 모바일은 두 열로 배치합니다.

홈의 주요 학습 카드에 개념·추천 이유·예상 시간을 표시합니다. 오늘의 5문제는 동일한 `DailySelection`과 공개 문제은행을 사용해 안내합니다. 취약 개념은 최근 정답률 60% 미만 기준을 설명하고, 기록이 없으면 골고루 학습한다고 안내합니다. 완료한 오늘 세트·복습 날짜가 된 오답·저장된 풀이에는 해당 상태에 맞는 이유를 표시합니다. 예상 시간은 남은 문항당 약 1분의 안내값이며 실제 풀이 시간이나 학습 수준을 측정한 값은 아닙니다. 아직 학년·과목을 정하지 않은 첫 방문 화면에는 구체적인 개념을 임의로 추천하지 않습니다.

로그인 창의 ‘아이디·비밀번호 찾기’에서 이 브라우저에 남은 마지막 아이디를 버튼으로 확인하고 로그인 칸에 넣을 수 있습니다. 공용 기기의 다른 학생 아이디일 수 있음을 안내합니다. 기록이 없으면 전에 로그인한 기기 또는 선생님 확인을 안내하며 서버의 학생 목록을 공개하지 않습니다. 비밀번호는 선생님이 학생 확인 후 초기화하는 기존 절차를 안내합니다. 복구 코드·이메일을 통한 학생 직접 재설정은 제공하지 않습니다.

홈의 주요 학습 버튼은 저장된 풀이가 있으면 ‘풀던 문제 이어하기’를 우선합니다. 현재 계정 또는 비회원의 유효한 임시 풀이 중 가장 최근 항목 하나를 연결하며, 클릭하면 문제 화면에서 답·필기·힌트·채점 상태를 바로 복원합니다. 삭제한 원래 오답에 연결된 확인 문제는 홈에서 제외합니다. 임시 풀이가 없으면 기존 오늘의 복습/5문제 안내를 유지합니다.

오늘의 5문제와 비슷한 확인 문제는 답안·선택지·현재 문항·열어 본 힌트·채점 상태·펜 필기를 자동 저장합니다. 다시 접속하면 ‘풀던 문제 이어하기’를 표시하며 필기도 계속 편집할 수 있습니다. 날짜가 바뀌어도 시작한 날짜와 문제를 유지합니다. 학생 계정과 비회원 풀이를 분리하고, 완료하면 임시 풀이를 정리합니다. ‘처음부터 새로 풀기’는 기존 임시 풀이를 대체합니다. 임시 풀이는 같은 기기·브라우저에만 보관하며 다른 기기로 동기화하지 않습니다. 저장 공간이 부족하면 기존 필기를 삭제하지 않고 안내하며, 오답이나 결과 저장에 실패하면 임시 풀이를 유지하고 재시도합니다.

오답은 처음 다시 맞히면 1일 뒤, 예정일에 맞히면 그 시점에서 3일 뒤, 다시 맞히면 7일 뒤 확인하며 마지막 정답에서 완료됩니다. 예정일 전 연습은 단계를 올리지 않고, 틀리면 처음부터 다시 시작합니다. 기존 완료 기록은 유지하며 로그인 시 복습 일정도 함께 동기화됩니다. 홈의 ‘지금 할 공부’와 오답노트의 ‘오늘 복습’에서 예정일이 지난 문제를 확인합니다.

복습 정답 결과와 다시 맞힌 오답 카드에 ‘비슷한 문제로 확인하기’를 표시합니다. 확인 문제은행은 총 114문항이며, 같은 학년·개념에서 원문과 다른 문항을 고르고 원래 과목과 세부 유형을 우선합니다. 기초·표준·도전 난도 다음에 세부 유형을 선택할 수 있습니다. 모든 확인 문항의 오답에서 원문을 제외한 세 난도 대체 문항이 연결되지만, 모든 세부 유형이 모든 난도에 있는 것은 아닙니다. 각 문항에 3단계 힌트와 해설을 제공합니다. 난도는 풀이 단계·개념 결합 정도에 따른 분류이며 실제 학생 정답률로 보정한 값은 아닙니다. 추가 확인 문항은 오늘의 5문제 구성에 넣지 않습니다.

오늘의 5문제는 해당 과목에서 정답률 60% 미만인 개념과 복습일이 된 오답의 개념을 최대 3문제까지 우선합니다. 나머지는 다른 개념과 미선택 문제로 균형을 맞춥니다. 기록이 없으면 기존의 균형 구성을 사용합니다. 완료한 당일 세트의 문항 목록을 기록해 같은 날 재풀이 때 유지하며, 구버전 기록에는 문항 목록이 없으므로 기존 날짜별 선정 방식을 사용합니다. 정답 개수·총 5문제·연속 학습 기록 형식은 유지합니다.

선생님 방의 학생별 ‘오답·힌트 분석 보기’에서 보관된 오답 원인, 확인 문제 풀이 횟수·힌트 사용률·평균 사용 단계·힌트 없이 맞힌 횟수를 확인할 수 있습니다. 반 카드에는 많이 기록한 원인과 합산 힌트 현황을 표시합니다. 원인은 현재 보관된 노트 기준이며 삭제한 노트는 제외됩니다. 힌트 누적 집계는 기능 적용 이후 확인 문제의 모든 정답·오답 시도를 기기별 카운터로 합산하고, 오답 재풀이를 확인 문제 시도로 중복 집계하지 않습니다. 이전 노트의 힌트 기록은 별도 문제 수로 표시하며 과거의 전체 사용률을 추정하지 않습니다.

힌트는 학생이 버튼을 눌러 개념 → 접근 방법 → 다음 풀이 단계 순으로 확인합니다. 채점 후 힌트 사용 단계를 안내하며, 새 오답에는 난도와 사용 단계도 저장합니다. 오답 원인은 개념·조건 해석·계산·시간·아직 모름 중 선택하고 오답노트에서 수정하거나 비울 수 있습니다. 학생이 고른 원인이며 자동 진단으로 해석하지 않습니다. 원인 수정은 복습 일정을 바꾸지 않고 계정 동기화에 포함됩니다. 태블릿 풀이판·채점을 제공하고 개념 통계와 새 오답에 반영하되 원래 문제의 복습 일정과 오늘의 5문제 점수에는 영향을 주지 않습니다.

### 상단 메뉴

다섯 페이지 모두 같은 메뉴를 쓴다. 순서는 **공지 · 직접 보는 수학 · 개념 지도 ·
자료실 · 질문**. 예전에는 "직접 보는 수학"만 따로 검은 단추(`.nav-actions`)로
빼 두었는데, 항목이 다섯이 되면서 그 단추는 없앴다 — 하나만 강조하면 나머지
넷이 곁다리처럼 보였다.

960px 이하 폭(폰·태블릿)에서는 다섯 개 전부 오른쪽 위 햄버거 버튼 안으로 들어간다.
자바스크립트 없이 체크박스만으로 여닫히므로(`style.css`의 `.nav-toggle-*`), 새 페이지를
만들 때도 헤더 블록을 그대로 복사하면 폰 메뉴가 함께 따라온다.
햄버거의 누르는 영역은 44×44px(권장 최소치)이고, 막대 3개는 20px 그대로다 —
`.nav-toggle`의 `margin-right: -6px`가 넓어진 만큼을 되돌려 아이콘 위치를 유지한다.
지금 있는 페이지의 링크에는 `aria-current="page"`를 달아 옅은 회색으로 표시한다.

### 어두운 화면 (다섯 페이지 전부, 켜고 끄는 것)

오른쪽 위 달/해 단추. **자료 페이지(`demos/*.html`)는 이 기능이 없다** — 그래프를
그리는 곳마다 색이 코드 안에 직접 박혀 있어서(`ctx.strokeStyle = "#000"` 같은 식),
배경만 검게 바꾸면 선이 안 보이게 된다. 그래서 다섯 개 '쉘' 페이지에만 켠다.

**작동 방식**

- `assets/theme.js` — 두 부분으로 나뉜다.
  1. `<head>` 안에서 defer 없이 바로 실행되는 부분. `localStorage` 에 저장된 값을 읽어
     `<html>` 에 `theme-dark` class 를 붙인다. 여기가 늦으면 흰 화면이 잠깐 보였다가
     검게 바뀌는 깜빡임이 생기므로, 이 스크립트는 반드시 `<head>` 초반에 있어야 한다.
  2. 버튼이 생긴 뒤(`DOMContentLoaded`) 클릭을 연결하는 부분. 누를 때마다 class 를
     붙였다 뗐다 하고 `localStorage` 에 다시 적는다.
- `style.css` 의 `:root` 바로 아래 `html.theme-dark { ... }` — `--canvas`·`--ink`·
  `--primary`(검정 → 파랑) 같은 변수를 다시 정의한다. 대부분의 요소는 이 변수를
  그대로 쓰므로 저절로 따라온다.

**저절로 안 따라오는 것들** — 파일 맨 끝 "어두운 화면 — 나머지 오버라이드" 구역에
따로 적어 뒀다. 두 부류로 나뉜다.

1. `rgba(0,0,0,.4)` 처럼 화면 배경과 상관없이 늘 정해진 색을 쓰던 곳
   (`.eyebrow`, `.caption`, `.card .use` 등)
2. 자바스크립트가 그리는 그림이라 CSS 변수가 안 닿는 곳 — 로고, 히어로의 단위원·
   사인곡선, 검색 결과의 학습지 아이콘. 이런 곳은 `style.css` 가 아니라 각 `.html`
   안에서 `stroke="#000"` 을 `stroke="currentColor"` 로 바꿔 뒀다 (`assets/demos.js`
   의 카드 아이콘은 예외 — 항상 밝은 파스텔 칩 위에 놓이므로 고정 검정 그대로 둔다).

**연두(`--block-lime`) 위에 놓이는 글자는 예외다.** 공지 배지, 개념 지도의
"이어지는 것" 상자, "8개 · 배우는 순서" 뱃지 — 셋 다 배경이 밝은 연두로 고정이라,
화면이 어두워져도 글자는 계속 고정된 어두운 색이어야 한다. `--ink` 를 그대로 뒀으면
어두운 화면에서 흰 글자가 연두 위에 놓여 안 보였다.

**`--inverse-canvas`/`--inverse-ink` 를 새로 쓰지 않는 이유.** 이 둘은 '늘 검정/늘
흰색' 고정값이다. `block-navy`(질문 페이지 Q&A)처럼 배경 자체가 항상 어두운 곳엔
맞지만, 개념 지도의 '고른 개념' 상자처럼 배경이 `--ink`(화면 따라 뒤집힘)인 곳에
`--inverse-ink`를 그대로 쓰면 어두운 화면에서 흰 배경 위에 흰 글자가 된다. 그런
곳은 `--canvas`(그 화면의 반대쪽 색)를 쓴다 — 밝은/어두운 화면 모두에서 맞는다.

### 홈 첫 화면 — 문은 둘뿐이다 (`index.html`)

**로그인 / 로그인 없이 써 보기.** 처음 온 학생이 고를 것은 이 둘이다.
회원가입은 로그인 단추 아래 `처음이에요? 회원가입` 글씨 한 줄.

이 입구는 두 번 다시 늘어났다. 마지막엔 로그인·회원가입·자료 둘러보기·가입 없이
체험하기·아이디·비밀번호 찾기 다섯 개였다. 그런데 '자료 둘러보기'는 바로 아래
'이 사이트에 있는 것'·위쪽 메뉴 '둘러보기'와 같은 일이고, '아이디·비밀번호 찾기'는
로그인 창 안에 이미 있다(잊은 학생도 로그인부터 누른다). '가입 없이 체험하기'는
맛보기처럼 들리지만 실제로는 기록도 남고 오답노트도 쓰는 길이라 '로그인 없이 써
보기'로 이름을 바꿨다. `check-home-portal` 이 첫 카드의 단추가 둘, 글씨가 하나인지 본다.

**맨 위 메뉴는 다른 쪽과 같다** — 컴퓨터는 메뉴 줄, 폰은 ☰. 한때 홈만 메뉴를 숨기고
'둘러보기'(아래 '이 사이트에 있는 것'으로 내려가기)를 두었는데, 로그인한 학생은 카드가
길어 그 칸이 첫 화면 밖으로 밀렸고, 홈만 맨 위가 다르게 생겼다. `check-home-portal` 이
홈 메뉴가 다른 쪽과 같은 일곱 개인지, 폰에서 ☰ 를 누르면 실제로 열리는지 본다.

공용 컴퓨터 보호는 그대로다 — 로그인하지 않은 채 홈을 열면 앞 사람의 기록을
보여 주지 않고 이 첫 카드가 나온다. '로그인 없이 써 보기'를 눌러야 그 브라우저의
기록이 열린다(`math-home-explore`, 창을 닫으면 사라짐).

그 전에는 문이 셋이었다. 오른쪽 위 `내 기록` 단추 안에도 가입·로그인이 있었고,
가운데에는 '내 학습 홈 만들기'라는 입력 칸이 따로 있었다. 가운데 것은 같은
일(학년·과목 정하기)을 하면서 이 기기에만 저장돼서, 학생은 같은 것을 두
군데에서 고르게 됐다. 그래서 가운데 폼을 없애고 학년·과목을 **가입 화면 안으로**
넣었다. 계정 단추는 로그인한 뒤에만 보인다.

- 가입 = `api/student-account.js`. **네 가지만 묻는다** — 이름(선택)·학년·아이디·
  비밀번호. 과목은 묻지 않는다. 처음 온 학생에게 "공통수학2 와 대수 중 무엇을
  주로 하느냐"는 답하기 어려운 질문이고, 학년에 맞는 기본 과목으로 시작해
  홈의 '학년·반·과목 변경'에서 언제든 바꿀 수 있다.
- 비밀번호는 **숫자 6~12자리**. 숫자 자판으로 치기 쉬우라고 숫자로 두되, 네 자리는
  1만 가지뿐이라 6자리로 올렸다. `111111` 처럼 같은 숫자, `123456`·`987654` 처럼
  이어지는 숫자는 막는다. 화면과 서버가 **같은 규칙을 따로** 본다(서버가 진짜 관문).
  규칙을 조이기 전에 만든 4자리 계정은 **그대로 로그인된다** — 쫓아내면 안 된다.
- 로그인 횟수 제한은 아이피가 아니라 **아이디별**로 센다. 학교는 아이피를 같이 쓰므로
  아이피로 세면 한 반이 로그인할 때 뒷자리 학생이 막힌다.
- 학년·오늘의 학습 기록·오답노트가 계정에 올라가, 폰에서 풀고 학교 컴퓨터에서
  이어 볼 수 있다.
- 필기 이미지는 서버로 보내지 않고 원래 기기에 보존한다. 삭제 시각을 함께 맞춰
  다른 기기의 오래된 오답이 되살아나지 않게 하고, 삭제 후 새로 틀린 문제는 다시 저장한다.
  새 풀이 횟수는 화면별 누적값을 합산하므로 재전송해도 중복되지 않는다. 이전 누적 기록은
  기준값으로 보존하지만, 과거에 이미 빠진 개별 풀이나 사라진 이미지를 복원할 수는 없다.
  동기화 개선 전부터 열어 둔 화면은 새로고침해야 한다. 요청의 계정과 로그인 계정을 대조해
  다른 창에서 계정을 바꿨을 때 이전 학생의 기록이 새 계정으로 올라가는 것을 막는다.
- 가입은 **강요하지 않는다.** 둘러보기로 들어와도 문제를 풀고 오답노트를 쓸 수
  있다(기록이 이 기기에만 남을 뿐). **고른 뒤에는 가입 이야기를 다시 꺼내지 않는다.**
  한때 기록이 쌓이면 "이 기기에만 있습니다" 하는 줄을 띄웠는데, 닫을 수가 없어서
  가입 생각이 없는 학생에게는 계속 붙어 있는 잔소리가 됐다. 그래서 뺐다.
- 가입 화면에 **선생님이 학습 기록을 본다는 것을 적어 둔다**(`assets/student-account-ui.js`).
  선생님 방 → 학생 학습 현황 → 학생별 **비밀번호 초기화**에서 새 숫자 비밀번호를 두 번 입력한다.
  가입과 같은 숫자 6~12자리 규칙을 적용하고, 기존 로그인 세션을 해제한다. 새 비밀번호는
  지문만 저장하며 기존 학습 기록은 유지한다. 새 비밀번호는 선생님이 해당 학생에게 직접 전달한다.
  학생 현황에서는 최근 7일 미학습과 아직 시작하지 않은 학생을 따로 골라 볼 수 있다.
  신규 가입 학생은 가입 7일 후부터 미학습에 포함한다. 반 공통 취약 개념은 해당 개념을
  푼 학생 중 정답률 60% 미만인 학생이 2명 이상일 때 상위 3개를 표시한다. 평균은 학생별
  정답률의 평균이며, 반이 없는 학생은 공통 개념 집계에서 제외한다. 이 표시는 학습 지도용이며 알림을 전송하지 않는다.
  나중에 알게 되는 편이 훨씬 나쁘다. 질문(`ask.html`)은 계정과 엮여 있지 않아
  그대로 익명이다.

수학 탈출(`escape.html`)은 이 목록에 **두지 않는다.** 게임 목록(`games.html`)
안에서 들어간다 — 게임이 홈과 게임 목록 두 군데로 나뉘어 보이면 안 되기 때문이다.
대신 `check-home-portal` 이 게임 목록에 수학 탈출이 실제로 있는지 따로 확인한다
(양쪽에서 빠지면 아무도 못 가는 쪽이 된다).

### 단추 — 규칙은 둘뿐이다

값은 `assets/style.css` 맨 위 `--btn-*` 에 **한 번만** 적는다. 페이지마다 단추를
따로 그리다 보니 한때 모양이 32가지였다(남색·검정·파랑, 알약·둥근 네모·각진 네모,
높이 34~81px).

| 역할 | 모양 | 쓰는 곳 |
|---|---|---|
| 주 단추 | **검정 알약** (어두운 화면에서는 흰 알약) | "누르면 뭔가 일어남". 한 화면에 하나 |
| 보조 단추 | 흰 알약 + 가는 테두리 | 그 밖의 행동 |

크기는 보통(48px)·작게(40px) 두 가지뿐. 새 단추는 `btn btn-primary` /
`btn btn-secondary` 를 쓰거나, 따로 그려야 하면 `--btn-*` 값을 가져다 쓴다.
`scripts/check-buttons.cjs` 가 어긋난 주 단추를 잡는다.

**칩**(학년·과목처럼 고르는 것)은 `--chip-*` 를 쓴다. 흰 알약 + 가는 테두리,
높이 40, **켜지면 라임**. 검정은 주 단추의 색이라 칩에 쓰지 않는다 — 한때 개념
지도·자료실만 켜진 칩이 검정이라 주 단추와 헷갈렸다. 같은 검사가 칩도 본다.

**페이지 머리 띠**(`.page-head`)는 모든 쪽이 같은 것을 쓴다(수학 탈출도). 공부 쪽은
라임, 찾기 쪽은 라일락, 놀이·질문 쪽은 코랄. 폰에서는 제목 한 줄만 남기고 설명을
감춘다 — 설명까지 넣으면 띠 하나가 첫 화면의 1/4 을 차지했다(62~134px → 모두 54px).

**게임은 하나의 틀을 쓴다.** 미니게임(`quick-game.html`)과 수학 탈출(`escape.html`)은
둘 다 `← 게임 목록` → 머리 띠(`.page-head`, 코랄) → 카드 셋으로 되어 있다:
시작(`.start-panel`) · 진행(`.quiz-panel`) · 결과(`.result-panel`). 이 규칙들은
`style.css` 끝의 '게임 틀' 한 곳에만 있다. 진행 카드 맨 위 한 줄에 '어디까지 ·
남은 시간', 그 아래 진행 막대와 점수. 한때 미니게임은 큰 라임 카드에 가는 58px
제목, 수학 탈출은 가운데 54px 시계·50px 방 이름·90px '탈출 성공!' 이라 둘이 서로
다른 화면이었다. `scripts/check-games.cjs` 가 수학 탈출을 한 판 돌려 확인한다.

**짙은 색 판을 쓰지 않는다.** 질문 쪽은 한때 쓰는 칸과 목록을 짙은 남색 판에 넣어서
폰 첫 화면이 거의 남색이었고 입력칸 글씨가 흐렸다. 이제 쓰는 칸은 밝은 카드
(`.ask-card`), 목록은 그 아래 바탕에 둔다. 입력칸·칩·단추는 다른 쪽과 같다.

**빈 화면**은 한 덩이로. 처음 온 학생에게 `0 · 0 · 0` 숫자 카드나 고를 것 없는 탭을
보여 주지 않는다(오답노트 — `scripts/check-wrong-notes.cjs`).
오답노트는 **오답이 하나도 없으면** 숫자 카드와 탭을 감춘다. 처음 온 학생만이 아니라
문제를 다 맞힌 학생도 마찬가지다(처음엔 앞의 경우만 감춰서 다 맞힌 학생에게 0·0·0 이
남아 있었다). 푼 기록이 있으면 개념별 진단은 그대로 둔다.

홈은 한때 남색 테마(배경·글자·테두리)를 따로 갖고 있어서 다른 사이트처럼 보였다.
`assets/home.css` 의 `--home-*` 는 이제 사이트 공통 색을 가리킨다.

### 홈 가운데 — 찾기는 뺐다 (`index.html`)

이 자리는 네 번 바뀌었다. **공지 목록 → 탭 세 개 → 검색칸 하나 → 없앰.**

검색칸을 넣은 이유는 "그거 어디 있어요"가 학생이 실제로 하는 유일한 질문이라
생각해서였다. 그런데 홈을 '가입 / 둘러보기' 둘로 정리하면서, 검색칸은 접히는
칸(`둘러보기`) 안쪽, 활동 아홉 개 **아래**로 밀려났다. 거기까지 내려온 학생은
이미 아홉 개를 보고 어디로 갈지 정한 뒤다. 즉 검색이 풀어 주던 문제를 그 위
목록이 먼저 풀어 버린다.

게다가 `files.html`·`library.html`·`map.html` 은 저마다 자기 검색칸을
갖고 있다. 홈 검색의 유일한 강점(세 곳을 한꺼번에)이 쓰일 자리가 없어진 것이다.

같이 뺀 것: 홈이 `demos.js`·`concepts.js`·`files.js` 28KB 를 검색 때문에만
불러오고 있었는데, 이제 안 불러온다. 첫 화면이 그만큼 빨라진다.

### 공지 — 접히는 한 줄

`index.html` 의 `<details class="notice-strip">`, **히어로 바로 아래**에 있다.
맨 위 한 개만 보이고 ＋ 를 누르면 나머지가 펼쳐진다. `NOTICES` 배열이 비면 줄 자체가
사라지므로 빈 게시판이 남지 않는다. 다른 페이지의 "공지" 메뉴(`index.html#notice`)로
들어오면 펼친 채로 뜬다.

### 자료실 — 내려받는 파일 (`files.html`)

파일은 **자료실에서 바로 올린다** — `files.html?admin` 으로 들어가 선생님 방과 같은
암호를 넣으면 올리는 칸이 생긴다(`api/files-admin.js`). 올린 것이 없으면 "아직 올린
파일이 없습니다" 한 줄만 나온다. 예전에는 `assets/files.js` 에 손으로 적었는데,
한 줄 올리려고 코드를 고쳐야 해서 결국 아무도 안 올리게 됐다. 그 파일은 지웠다.
PDF 는 `files/` 폴더에 넣고, **파일 이름에 띄어쓰기를 쓰지 않는다**
(주소가 깨져 내려받기가 안 될 수 있다). `files/README.md` 도 참고 —
GitHub 에서 그 폴더를 열면 바로 보인다.

카드가 아니라 줄로 둔 이유: 파일은 그림으로 알아볼 것이 없다. 날짜 · 제목 ·
내려받기 세 칸이면 충분하고, 줄이면 열 개가 넘어가도 한 화면에 들어온다.

### 개념 지도 (`map.html`)

같은 자료 17개로 들어가는 **두 번째 입구**다. `library.html` 이 "무엇이 있나"라면
개념 지도는 "지금 배우는 게 어디서 왔나"에 답한다.

고칠 곳은 `assets/concepts.js` 세 군데뿐이다 (홈의 찾기도 이 파일을 읽는다):

- `NODES` — 개념 19개. 각 개념의 `demos` 배열에 자료를 한 줄씩 매단다.
  열쇠말(`trig`, `poly` …)이 곧 주소가 된다 → `map.html?n=trig`
- `LAYERS` — 배우는 순서대로 쌓은 층. 여기 적힌 순서가 화면 순서다
- `EDGES` — `[먼저, 나중]`. "이게 있어야 저게 된다"

**개념 상자의 좌표는 어디에도 적혀 있지 않다.** 배치는 CSS(flex)가 하고,
script 는 그려진 자리를 재서 선만 얹는다 — 그래서 폰이든 데스크톱이든
저절로 맞는다. 좌표를 손으로 박는 순간 좁은 화면에서 반드시 깨진다.

같은 줄에 나란히 놓인 두 개념(예: 평면벡터 → 공간도형)은 위아래로 이으면
선이 거꾸로 올라가므로, 옆으로 잇고 아래로 부풀린다.

`map.html?n=trig` 처럼 개념을 지정해 링크를 보낼 수 있다 (수업 중에 쓰기 좋다).

#### 개념을 골랐을 때 — 상자가 답한다

예전에는 **선만** 밝히고 상자는 그대로 두었다. 그러면 얇은 선을 눈으로 따라가야
답을 알 수 있었다. 지도가 하려는 말이 "이게 있어야 저게 된다"인데 그 답이 선
하나에만 실려 있던 셈이다. 지금은 상자 자체가 답한다.

| 표시 | 뜻 | CSS |
| --- | --- | --- |
| 검정 채움 | 고른 개념 | `.cmap-node.on` |
| 검은 테두리 | 먼저 알아야 하는 것 | `.cmap-node.pre` |
| 연두 채움 | 여기서 이어지는 것 | `.cmap-node.post` |
| 흐림 | 관계없음 | `.cmap.has-selection .cmap-node` |

테두리를 `border-width` 로 두껍게 하지 않고 `box-shadow: inset` 으로 그린다.
`box-sizing: border-box` 라 테두리가 굵어지면 안쪽 폭이 줄어 글자가 미세하게
움직이는데, 그림자는 자리를 안 먹으므로 상자가 흔들리지 않는다.

색이 세 가지면 읽는 법이 필요하다. 지도 위 `.cmap-legend` 가 그 역할을 하고,
**개념을 고르기 전에는 숨어 있다** — 아직 읽을 색이 없기 때문이다.

#### "여기까지 오는 길 전부 보기"

지도 위 스위치(`#cmapDeep`). 끄면 **한 단계**, 켜면 **거슬러 올라가는 사슬 전체**를
밝힌다. 학생이 실제로 하는 질문이 "미적분Ⅱ 하려면 뭘 알아야 해요"인데, 그 답은
한 단계가 아니라 사슬 전체이기 때문이다.

예를 들어 **적분법**을 고르면 — 끄면 앞이 2개(적분·미분법), 켜면 **8개**가 나온다:

> 다항식 → 함수와 그래프 → 지수함수와 로그함수 · 삼각함수 · 함수의 극한과 연속
> → 미분 · 적분 → 미분법

**나오는 순서가 곧 공부 순서다.** `앞전부()` 가 모은 것을 `LAYERS` 순서
(= 배우는 순서)로 정렬해 돌려주기 때문이다. 그래서 패널 제목에 "8개 · 배우는 순서"
라고 적어 둔다.

뒤쪽(이어지는 것)은 스위치와 상관없이 **늘 한 단계만** 보여 준다. 양쪽 다 전부
펼치면 가운데쯤 있는 개념에서는 거의 모든 상자가 켜져서 아무것도 구별되지 않는다.

`EDGES` 는 배우는 순서대로 난 길이라 되돌아오는 고리가 없다. 그래도 `앞전부()` 는
이미 담은 것을 건너뛰므로, 여러 갈래로 만나는 개념도 한 번만 나오고 실수로
고리를 만들어도 멈추지 않는 일은 없다.

### 제목 단계 (h1 → h2 → h3)

페이지마다 `h1`은 하나뿐이고, 그 아래로 단계를 건너뛰지 않는다. 검색 노출과
화면낭독기가 이걸 보고 페이지 제목을 잡으므로, 새 페이지를 만들 때도 지켜 주세요.

| 페이지 | h1 | h2 | h3 |
|---|---|---|---|
| `index.html` | 수학을 보다 (히어로) | 뭘 찾고 있나요 | — |
| `library.html` | 직접 보는 수학 | 과목 이름 (`.grid-head`) | 자료 카드 제목 |
| `map.html` | 개념 지도 | 층 이름 · 고른 개념 이름 | 먼저/이어지는/자료 |
| `files.html` | 자료실 | — | — |
| `ask.html` | 공부 방법, 편하게 물어보세요 | 받은 질문과 답 | 질문 한 건씩 |

푸터에는 제목이 없다. 예전에는 `Menu` 라는 `h3` 가 있었는데, 링크가 가로
한 줄이 되면서 이름표 없이도 무엇인지 보여서 뺐다 — 덕분에 단계를 신경 쓸
일도 없어졌다.

`library.html`의 과목 이름은 `render()` 안에서 `<h2>`로 만든다. 태그를 바꾸면
`style.css`의 `.grid-head h2` 선택자도 같이 고쳐야 글자 크기가 유지된다.

### 수업용 링크

자료를 열고 슬라이더를 원하는 값에 맞추면 **주소가 그 상태로 바뀝니다.**
오른쪽 위 **"링크 복사"** 를 눌러 그대로 보내면, 받은 사람도 같은 화면으로 열립니다.

demos/riemann.html?n=40&mode=right                직사각형 40개, 오른쪽 끝 값

주소에는 **기본값과 다른 것만** 담기므로 짧게 유지됩니다.
`assets/state.js` 가 전 자료에서 공통으로 처리하니 자료를 새로 만들어도
맨 아래 `<script src="../assets/state.js"></script>` 한 줄이면 됩니다.
(몬티 홀처럼 슬라이더가 없는 자료에서는 버튼이 생기지 않습니다)

데모 한 개 = HTML 파일 한 개. 서로 영향을 주지 않으므로 마음 편히 추가·수정할 수 있다.

## 글 올리는 법

- **움직여 보는 자료** — `assets/demos.js` 의 `DEMOS` 배열 **맨 아래에** 추가합니다.
  비슷한 항목을 복사해서 고치면 됩니다. 홈의 찾기와 `library.html` 이 함께 봅니다.
  - `fig` : 카드와 검색 결과에 들어가는 작은 그림 (SVG)
  - `use` : 카드에 보이는 "이럴 때" 한 줄 — 수업에서 언제 꺼내 쓰는지
  - `desc` : 화면에는 안 나오지만 **검색에는 걸리는** 설명문 (`keywords` 와 같은 역할)
  - `d3: true` : 3D 자료에 붙는 검은 **3D** 배지
  - 과목 색과 목차는 `subject` 값을 보고 자동으로 붙습니다 (색은 `style.css` 의 `--sub-*`)
- **내려받는 파일** — 코드에 적지 않습니다. `files.html?admin` 에서 바로 올립니다
- **개념** — `assets/concepts.js` 의 `NODES`. 자료를 만들면 해당 개념의
  `demos` 배열에 한 줄 매답니다 (그래야 개념 지도에서도 그 자료로 갈 수 있습니다)
- **질문·답변** — `ask.html` 아래쪽 `QNA` 배열 (최신 글을 맨 앞에)
- **공지** — `index.html` 아래쪽 `NOTICES` 배열 (최신 글을 맨 앞에).
  홈에서는 맨 앞 한 개만 한 줄로 보이고 나머지는 ＋ 안에 접힙니다

한 줄 추가하고 파일을 올리면 화면에 그대로 반영된다.

과목이 하나 늘거나 이름이 바뀌면 `assets/demos.js` 의 `SUBJECTS` 만 고치면 된다.

과목 목록을 빼면서 그 부담이 없어졌다 — 아래 "푸터" 참고)

### 푸터

다섯 페이지 모두 같은 푸터를 쓴다. **딱 한 줄**이다 — 왼쪽에 이름, 오른쪽에
링크 다섯 개, 그 아래 쓰는 법 한 줄. 검은 색면(`--inverse-canvas`) 위에 흰 글씨다.

푸터는 '끝났다'는 표시지 두 번째 홈페이지가 아니다. 예전에는 과목 6개를 다시
나열하느라 홈 전체 높이의 31%(577px)를 차지했다. 지금은 데스크톱 **115px** 다.
링크를 다시 늘리고 싶어질 때 이 숫자를 기억해 두면 좋다.

**줄여 온 순서** — 한 번에 줄인 게 아니라 네 번에 걸쳐 줄였고, 매번 원인이
달랐다. 같은 실수를 반복하지 않으려고 적어 둔다.

1. **577px** — 3단(브랜드 / Menu / Contact). Contact 칸에 항목이 **하나뿐**이라
   오른쪽이 허전하게 비었다. 링크를 한 목록으로 합쳐 2단으로.
2. **380px** — 2단인데도 높았다. 링크 5개가 **세로로 쌓여** 오른쪽이 5줄인데
   왼쪽은 2줄에서 끝났다. 칸 높이는 둘 중 긴 쪽을 따라가므로 왼쪽 아래에 200px
   넘는 빈자리가 생긴 것. 링크를 가로 한 줄로 눕혀서 해결.
3. **250px** — 그러고 나니 왼쪽에 한 줄이 더 들어갈 자리가 생겨 자료 요약
   (`자료 17개 · 마지막 업데이트 …`)을 넣었다.
4. **115px** — 소개 문구와 자료 요약을 다시 뺐다. **자리가 남는다고 채운 것이
   문제였다.** 상단 바와 홈에 이미 있는 말이라, 여기서 또 하니 페이지가 두 번
   끝나는 것처럼 보였다. 남는 자리는 비워 두는 편이 낫다.

> 그때 같이 지운 것들 — `.footer-grid` / `.footer-desc` / `.footer-stat`,
> `assets/demos.js` 의 요약 줄 계산, `ask.html`·`map.html` 이 그 계산 때문에
> 읽던 `assets/demos.js`. 지금 그 파일을 읽는 것은 홈과 `library.html` 둘뿐이다.

**왜 검은 색면인가.** 흰 바탕에 실선 한 줄만 그어 두니 '아직 본문인가' 싶게
이어져 보였다. 색이 바뀌면 줄 하나 없이도 여기가 끝인 게 보여서, `border-top`
은 지웠다. 대신 어두운 바탕에서 안 보이게 되는 것 세 가지를 함께 뒤집어 뒀다.
이 셋은 색을 다시 바꿀 때도 같이 따라다녀야 한다.

| 원래 | 검은 바탕에서 생기는 문제 | 바꾼 것 |
| --- | --- | --- |
| `.caption` `rgba(0,0,0,.58)` | 검정 위 검정 — 안 보임 | `.footer .caption` 흰색 55% |
| `:focus-visible` 검정 테두리 | 키보드로 다닐 때 지금 어디인지 안 보임 | `.footer :focus-visible` 흰색 |
| `.to-top` 검은 원 단추 | 끝까지 내리면 배경에 묻힘 | 흰 테두리 2px (흰 바탕에서는 티가 안 남) |

**폰(390px)에서는** 이름과 링크가 각자 한 줄씩 되어 174px 이다. 가로 스크롤은
생기지 않는다. 메뉴를 더 늘리면 링크가 세 줄이 되니 그때 다시 잰다.

- `files.html`의 **`FILES` 배열** — 학습지를 올리면 한 줄씩 (`files/README.md` 참고)

`og:image` · `og:url` 은 이미 실제 주소(`https://guns-math.vercel.app`)로
적혀 있습니다. 주소가 바뀌면 다섯 페이지에서 그 두 줄만 같이 고치면 됩니다.

### 질문을 실제로 받으려면

> **지금은 이렇게 동작한다 (2026년 9월)** — 아래 긴 설명은 예전 방식의 기록이다.
>
> - 학생 질문은 사이트 저장소(Upstash Redis)에 바로 저장되고 질문 페이지에 공개된다.
> - 답은 **선생님 방(`admin.html`)** 에서 단다. 답을 기다리는 질문이 맨 위에 모인다.
> - **새 질문 알림** — 선생님 방 → 받은 질문 → **이 기기에서 알림 받기**. 기기마다
>   한 번씩 켠다. 새 질문이 오면 그 기기에 알림이 뜨고, 누르면 그 질문 답 칸이 열린다.
>   **시험 알림 보내기** 로 제대로 오는지 확인할 수 있다. 따로 설정할 것은 없다
>   (필요한 열쇠는 처음 켤 때 서버가 만들어 저장소에 넣는다).
>   - 안드로이드·컴퓨터: 크롬·엣지·삼성 인터넷에서 바로 켜진다.
>   - 아이폰·아이패드: Safari 공유 단추 → **홈 화면에 추가** → 그 아이콘으로 열어서 켠다
>     (애플이 홈 화면에 올린 사이트에만 알림을 허락한다).
> - Formspree 메일은 예비로 남아 있다(`ask.html` 의 `폼주소`). 알림만 쓰려면 비워도 된다.

이 사이트는 서버 없이 파일만 올라가는 방식이라, **학생이 쓴 글을 사이트가 직접
저장할 수 없다.** 어딘가로 '보내는' 역할을 할 서비스가 하나는 필요하다.

**처음엔 구글 폼을 페이지 안에 심었었다.** 그런데 두 가지 문제가 있었다.
① 폼 안쪽(보라색 상단바, 구글 서체)은 남의 사이트라 이쪽에서 손댈 수 없어
사이트와 따로 놀았다. ② 사진 첨부 칸을 하나라도 넣으면 구글이 응답자에게
로그인을 강제해서, 응답에 학생 이메일이 남아 '익명'이 깨졌다.

**그래서 지금은 이 페이지 자신의 `<form>` 을 만들고, [Formspree](https://formspree.io)
(무료)가 그 내용을 선생님 이메일로 전달하기만 하는 방식으로 바꿨다.** 폼이 사이트
HTML 그 자체라 모양이 완전히 같고, 이름을 안 받으므로 진짜 익명이다. 학생 쪽에는
계정도 로그인도 없다 — 계정이 필요한 건 선생님(Formspree)뿐이다.

1. formspree.io 에서 계정을 만들고 New Form
2. 만들어진 Endpoint 주소를 복사 (`https://formspree.io/f/abcdwxyz` 모양)
3. `ask.html` 위쪽에 붙여 넣는다

```js
const 폼주소 = "https://formspree.io/f/abcdwxyz";
```

- `폼주소` 가 **비어 있으면** 칸이 잠기고 "질문 받는 곳을 준비하고 있습니다"
  한 줄만 나온다. 그래서 폼을 안 만든 상태로 둬도 페이지가 깨지지 않는다.
- 제출은 `fetch()` 로 처리한다. 성공하면 "질문이 전달됐습니다", 실패하면
  "지금은 안 보내져요"가 `.qform-status` 자리에 뜬다. 새로고침도, 페이지 이동도 없다.
- 이름 칸이 아예 없다 — Formspree 는 보낸 사람의 이메일을 요구하지 않는다.
  로그인도 없으니 학생이 누구인지 알 방법이 없다. 문제 사진처럼 계정이 꼭
  필요한 것을 받아야 한다면, 그때는 별도 페이지(구글 폼 링크 등)를 새로 만드는
  편이 이 폼의 익명성을 지키는 데 낫다.

답변은 Formspree 계정을 만들 때 쓴 이메일로 온다. 그중 공유할 만한 것을 `QNA`
배열에 옮겨 적으면 페이지 아래 "받은 질문과 답"에 쌓인다.

> **다른 방법도 있었다** — 카카오톡 오픈채팅(학생들이 이미 쓰는 앱이지만 밤에도
> 알림이 오고 질문이 흘러가 나중에 못 찾는다), Tally 같은 다른 폼 서비스(Formspree
> 보다 자체 UI가 있어 커스터마이징에 한계가 있다), 메일 주소만 걸어 두기(학생 폰에
> 메일 앱이 설정돼 있어야 열리고 주소가 공개돼 스팸이 온다). 사이트 안에 직접 만든
> 폼 쪽이 모양이 완전히 같고 진짜 익명이라 이걸 골랐다.

색을 바꾸고 싶으면 `assets/style.css` 맨 위 `:root` 의 값만 고치면 사이트 전체가 함께 바뀐다.

## 내 컴퓨터·폰에서 보기

**`폰으로 보기.bat` 을 더블클릭**하면 끝난다. 검은 창이 뜨면서 주소를 알려 준다.
그 창을 닫으면 서버가 꺼진다. (창은 켜 둔 채로 두면 된다)

- 이 컴퓨터에서는 `http://localhost:5173`
- 폰에서는 창에 찍히는 `http://192.168.…:5173` — **폰이 같은 와이파이에 있어야 한다**

폰용 주소는 공유기가 그때그때 정해 주므로 **켤 때마다 달라질 수 있다.** 외우지 말고
창에 찍히는 것을 그대로 보고 치면 된다 (`serve.js`가 매번 다시 찾아 준다).

3D 자료는 모듈을 불러오기 때문에, 파일을 그냥 더블클릭하는 방식(`file://`)으로는
열리지 않는다. 위 방법으로 열어야 하는 이유다.

명령창에 직접 치고 싶으면 이 폴더에서 `node serve.js`.

### 폰에서 안 열릴 때

1. 폰이 PC와 **같은 와이파이**인지 (폰의 데이터를 끄고 다시 해 보면 확실하다)
2. Windows 방화벽 창이 떴다면 '개인 네트워크'에 체크하고 [액세스 허용]
3. 그래도 안 되면 공유기의 '단말 간 차단(AP isolation)' 설정 때문일 수 있다 —
   이때는 아래 Vercel 로 올리는 편이 빠르다

올리고 나면 PC 를 켜 둘 필요도, 같은 와이파이일 필요도 없어진다.
학생은 링크만 누르면 되고, 폰에서도 그냥 열린다.

**이미 올라가 있다.** https://guns-math.vercel.app

- GitHub 저장소 — myunggun6348-beep/guns-math (**공개**)
- main 브랜치에 반영하면 Vercel이 자동으로 다시 배포한다.

### 선생님 방 암호

**바꾸는 곳: 선생님 방 맨 아래 "암호 바꾸기".** Vercel 설정에 들어갈 필요 없다.
암호는 저장소에 글자 그대로 남지 않고 알아볼 수 없게 뭉갠 지문만 남는다.

Vercel 환경 변수 `ADMIN_PASSWORD` 에 넣어 둔 처음 암호는 **여벌 열쇠로 계속
통한다** — 바꾼 암호를 잊어버려도 잠기지 않게 하려는 것이다. 그것까지 막으려면
Vercel 에서 그 값을 바꾼다. 암호는 코드에 없으므로 이 저장소가 공개여도 새지 않는다.

### 그 다음부터는 웹에서만 작업하면 된다

`github.com` 에서 파일을 열고 연필 아이콘으로 고친 뒤 **Commit changes** 를 누르면,
Vercel 이 알아서 다시 배포한다. 폰에서 새로고침하면 바뀌어 있다.
컴퓨터에 파일을 두고 명령어를 칠 필요가 없다.

`og:image` · `og:url` 은 이미 실제 주소로 적어 두었으니, 카톡으로 링크를 보내면
미리보기 그림이 뜬다.

## 새 자료 추가 순서

1. `demos/` 안에 새 HTML 파일을 만든다 (`projection.html`을 복사해서 시작하면 빠름,
   맨 아래 `<script src="../assets/state.js"></script>` 도 그대로 두면 수업용 링크가 함께 딸려 온다)
2. **`assets/demos.js`** 의 `DEMOS` 배열 **맨 아래**에 항목을 추가하고 `ready: true` 로 둔다
   (검색이 되도록 `keywords` 에 관련 용어를 넣어 둘 것)

그러면 이 셋이 저절로 따라온다:

- **`library.html`(직접 보는 수학)** — 과목별로 알아서 제자리에 들어간다.
  `SUBJECTS` 에 적은 과목 순서로 묶으므로, 배열의 어디에 넣든 상관없다.
  (예전에는 배열을 훑다가 과목이 바뀔 때마다 제목을 만들었다. 그래서 같은 과목을
  떨어뜨려 놓으면 제목이 두 번 생기고 같은 id 가 두 개가 되어 바로가기가 엉켰다.
  지금은 그 제약이 없다)
- **홈의 찾기** — 새 자료도 바로 검색된다. `keywords` 에 학생이 쓸 법한 말을
  넣어 둘수록 잘 걸린다
- **과목 칩의 개수** — 홈(빈 검색칸)과 `library.html` 위쪽 모두 배열을 세어 다시 붙인다

**한 가지는 저절로 안 된다** — 개념 지도에 매다는 것. `assets/concepts.js` 에서
해당 개념의 `demos` 배열에 `{ t: "제목", h: "demos/파일.html" }` 한 줄을 넣어야
개념 지도에서도 그 자료로 갈 수 있다. 이걸 빠뜨리면 자료는 잘 보이는데 개념 지도
쪽에서만 안 보이는, 알아채기 어려운 상태가 된다.

> `files.html`(자료실)은 `DEMOS` 와 **상관없다.** 그쪽은 내려받는 파일이라
> 코드가 아니라 저장소(`api/files.js`)에서 목록을 읽는다.
