# 수학을 보다

고등학교 수학에서 말로 설명하기 어려운 개념을 학생이 직접 움직여 볼 수 있게 만든 웹 자료실.
각 학습 화면은 독립되어 있고, 상단 메뉴와 푸터를 공유한다.

인터넷 주소: **https://guns-math.vercel.app**
(GitHub `main` 에 올리면 Vercel 이 알아서 다시 배포한다)

## 구조

```
index.html                 홈 (소개 + 공지 한 줄 + 찾기)
library.html                직접 보는 수학 — 화면에서 움직여 보는 자료 17개
map.html                    개념 지도 — 개념 19개의 선후 관계, 자료로 가는 또 다른 입구
files.html                  자료실 — 최근 3개년 기출 문제·정답·해설
solve.html                  기출문제 태블릿 풀이 — PDF 위 필기·자동 저장·채점
ask.html                    질문 — 학생이 묻고 선생님이 답하는 게시판
escape.html                 수학 탈출 — 15분 문제 풀이와 태블릿 필기 활동
files/                      위 자료실이 내려주는 PDF 들 (올리는 법은 그 안 README)
assets/demos.js            자료 목록 (DEMOS) — 홈의 찾기와 library.html 이 함께 씁니다
assets/concepts.js         개념 목록 (NODES/LAYERS/EDGES) — 홈의 찾기와 map.html
assets/exam-catalog.json   최근 3개년 EBSi 기출 목록
assets/file-library.js     학년·연도·검색 필터와 기출 링크
assets/solve.js · solve.css 태블릿 풀이 화면과 필기 저장
assets/files.js            직접 올린 파일 목록 (FILES) — 홈의 찾기와 files.html
assets/theme.js            어두운 화면 켜고 끄기 — 다섯 페이지가 함께 씁니다
assets/style.css           사이트 전체 공통 스타일
assets/state.js            수업용 링크 (조작값 ↔ 주소) — 모든 자료가 함께 씁니다
assets/og.png              카톡·문자 공유 미리보기 이미지 (1200×630)
assets/og-source.html      위 이미지를 다시 만들 때 쓰는 원본
assets/icon-192.png · 512  선생님 방을 폰 홈 화면에 올렸을 때의 앱 아이콘
assets/icon-source.html    위 아이콘을 다시 만들 때 쓰는 원본
manifest.webmanifest       선생님 방을 '앱'으로 올리기 위한 설명서 (아이폰 알림에 필요)
sw.js                      새 질문 알림을 받아 띄우는 일꾼 — 선생님 방에서만 등록됨
api/_push.js               새 질문 알림 보내기 (열쇠는 저장소에 알아서 만들어 둠)
assets/hit.js · api/hit.js 방문 세기 — 페이지별 열린 횟수만 (누가 열었는지는 안 셈).
                           선생님 방 '방문' 칸에서 본다. 새 페이지를 만들면 맨 아래에
                           <script defer src="/assets/hit.js"></script> 한 줄을 붙일 것
assets/vendor/             three.js · PDF.js · 폰트 (인터넷 없이도 열리도록 함께 보관)
폰으로 보기.bat            ← 더블클릭하면 홈페이지가 켜집니다 (아래 "내 컴퓨터·폰에서 보기")
serve.js                   위 .bat 이 실행하는 것 — 폰에서 볼 주소도 찾아서 알려 줍니다
```

**"직접 보는 수학"과 "자료실"은 다른 것이다.** 앞엣것(`library.html`)은 화면에서
직접 움직여 보는 것, 뒤엣것(`files.html`)은 내려받아 인쇄하는 것. 이름이 헷갈리기
쉬우니 새 항목을 어디에 넣을지 먼저 정하고 손대는 편이 좋다.

### 이름과 로고

사이트 이름은 **수학을 보다**다 (예전 이름 `GUN's MATH`). 로고는 **돋보기 안에
곡선** — 이름이 하는 말을 그림으로 한 번 더 하는 것이다. 예전에는 삼각산 모양이었는데
이름과 아무 상관이 없었다.

이름을 또 바꾸게 되면 손댈 곳이 **여섯 군데**다. 한 군데라도 빠지면 티가 난다.

| 어디 | 몇 개 | 비고 |
| --- | --- | --- |
| `<title>` | 22 | 자료 페이지 17개 포함 |
| `og:title` · `og:image:alt` | 5 | 카톡 미리보기에 나오는 글자 |
| 상단 내비의 `.brand` | 5 | 로고 SVG 도 여기 |
| 푸터의 `.footer-wordmark` | 5 | |
| 홈 히어로의 `h1` | 1 | |
| `assets/og-source.html` | 1 | 고친 뒤 아래대로 그림을 다시 만들 것 |

파비콘(주소창 아이콘)은 `<link rel="icon">` 의 data URI 로 22개 파일에 박혀 있다.
로고를 바꿀 때는 이것도 같이 바꿔야 탭에 옛 그림이 안 남는다.

**미리보기 이미지 다시 만들기** — `assets/og.png` 는 손으로 그리지 않는다.
`assets/og-source.html` 이 원본이고, 그걸 1200×630 으로 찍어서 만든다.
`폰으로 보기.bat` 을 켠 다음:

```
chrome --headless --window-size=1200,630 --screenshot=assets\og.png ^
       http://localhost:5173/assets/og-source.html
```

(크롬 경로는 보통 `C:\Program Files\Google\Chrome\Application\chrome.exe`)

**앱 아이콘 다시 만들기** — 로고를 바꾸면 `assets/icon-source.html` 의 SVG 도 같이
고치고, 같은 방법으로 두 크기를 찍는다.

```
chrome --headless --window-size=192,192 --screenshot=assets\icon-192.png ^
       "http://localhost:5173/assets/icon-source.html?s=192"
chrome --headless --window-size=512,512 --screenshot=assets\icon-512.png ^
       "http://localhost:5173/assets/icon-source.html?s=512"
```

### 상단 메뉴

다섯 페이지 모두 같은 메뉴를 쓴다. 순서는 **공지 · 직접 보는 수학 · 개념 지도 ·
자료실 · 질문**. 예전에는 "직접 보는 수학"만 따로 검은 단추(`.nav-actions`)로
빼 두었는데, 항목이 다섯이 되면서 그 단추는 없앴다 — 하나만 강조하면 나머지
넷이 곁다리처럼 보였다.

960px 이하 폭(폰·태블릿)에서는 다섯 개 전부 오른쪽 위 햄버거 버튼 안으로 들어간다.
자바스크립트 없이 체크박스만으로 여닫히므로(`style.css`의 `.nav-toggle-*`), 새 페이지를
만들 때도 헤더 블록을 그대로 복사하면 폰 메뉴가 함께 따라온다.
햄버거의 누르는 영역은 44×44px(권장 최소치)이고, 막대 3개는 20px 그대로다 —
`.nav-toggle`의 `margin-right: -6px`가 넓어진 만큼을 되돌려 아이콘 위치를 유지한다.
지금 있는 페이지의 링크에는 `aria-current="page"`를 달아 옅은 회색으로 표시한다.

### 어두운 화면 (다섯 페이지 전부, 켜고 끄는 것)

오른쪽 위 달/해 단추. **자료 페이지(`demos/*.html`)는 이 기능이 없다** — 그래프를
그리는 곳마다 색이 코드 안에 직접 박혀 있어서(`ctx.strokeStyle = "#000"` 같은 식),
배경만 검게 바꾸면 선이 안 보이게 된다. 그래서 다섯 개 '쉘' 페이지에만 켠다.

**작동 방식**

- `assets/theme.js` — 두 부분으로 나뉜다.
  1. `<head>` 안에서 defer 없이 바로 실행되는 부분. `localStorage` 에 저장된 값을 읽어
     `<html>` 에 `theme-dark` class 를 붙인다. 여기가 늦으면 흰 화면이 잠깐 보였다가
     검게 바뀌는 깜빡임이 생기므로, 이 스크립트는 반드시 `<head>` 초반에 있어야 한다.
  2. 버튼이 생긴 뒤(`DOMContentLoaded`) 클릭을 연결하는 부분. 누를 때마다 class 를
     붙였다 뗐다 하고 `localStorage` 에 다시 적는다.
- `style.css` 의 `:root` 바로 아래 `html.theme-dark { ... }` — `--canvas`·`--ink`·
  `--primary`(검정 → 파랑) 같은 변수를 다시 정의한다. 대부분의 요소는 이 변수를
  그대로 쓰므로 저절로 따라온다.

**저절로 안 따라오는 것들** — 파일 맨 끝 "어두운 화면 — 나머지 오버라이드" 구역에
따로 적어 뒀다. 두 부류로 나뉜다.

1. `rgba(0,0,0,.4)` 처럼 화면 배경과 상관없이 늘 정해진 색을 쓰던 곳
   (`.eyebrow`, `.caption`, `.card .use` 등)
2. 자바스크립트가 그리는 그림이라 CSS 변수가 안 닿는 곳 — 로고, 히어로의 단위원·
   사인곡선, 검색 결과의 학습지 아이콘. 이런 곳은 `style.css` 가 아니라 각 `.html`
   안에서 `stroke="#000"` 을 `stroke="currentColor"` 로 바꿔 뒀다 (`assets/demos.js`
   의 카드 아이콘은 예외 — 항상 밝은 파스텔 칩 위에 놓이므로 고정 검정 그대로 둔다).

**연두(`--block-lime`) 위에 놓이는 글자는 예외다.** 공지 배지, 개념 지도의
"이어지는 것" 상자, "8개 · 배우는 순서" 뱃지 — 셋 다 배경이 밝은 연두로 고정이라,
화면이 어두워져도 글자는 계속 고정된 어두운 색이어야 한다. `--ink` 를 그대로 뒀으면
어두운 화면에서 흰 글자가 연두 위에 놓여 안 보였다.

**`--inverse-canvas`/`--inverse-ink` 를 새로 쓰지 않는 이유.** 이 둘은 '늘 검정/늘
흰색' 고정값이다. `block-navy`(질문 페이지 Q&A)처럼 배경 자체가 항상 어두운 곳엔
맞지만, 개념 지도의 '고른 개념' 상자처럼 배경이 `--ink`(화면 따라 뒤집힘)인 곳에
`--inverse-ink`를 그대로 쓰면 어두운 화면에서 흰 배경 위에 흰 글자가 된다. 그런
곳은 `--canvas`(그 화면의 반대쪽 색)를 쓴다 — 밝은/어두운 화면 모두에서 맞는다.

### 홈 가운데 — 찾기 (`index.html`)

이 자리는 세 번 바뀌었다. **공지 목록 → 탭 세 개 → 검색칸 하나.**

탭(새로 올린 자료 / 오늘의 자료 / 과목별 자료)을 없앤 이유는, 셋 다
"자료를 어떻게 늘어놓을까"에 대한 답이었기 때문이다. 학생이 실제로 하는 말은
**"그거 어디 있어요"** 하나뿐이라, 그 질문 하나를 홈 한가운데로 끌어올렸다.

**세 곳을 한꺼번에 뒤진다.** 학생은 자기가 찾는 것이 '자료'인지 '개념'인지
'학습지'인지 미리 알 수 없다. 그러니 나눠서 찾게 하면 안 되고, 대신 결과를
묶어서 어디로 가는 것인지 밝혀 둔다.

| 묶음 | 어디서 오나 | 눌렀을 때 |
| --- | --- | --- |
| 직접 보는 수학 | `DEMOS` (`assets/demos.js`) | 그 자료 페이지 |
| 개념 지도 | `NODES` (`assets/concepts.js`) | `map.html?n=<열쇠말>` — 그 개념이 열린 채로 |
| 자료실 | `FILES` (`assets/files.js`) | PDF 바로 내려받기 |

| 상태 | 보여 주는 것 |
| --- | --- |
| 아무것도 안 침 | 과목 칩 6개 + 개수 (`SUBJECTS`) |
| 뭔가 침 | 묶음별로 줄, **묶음마다 넷까지** |
| 넷을 넘김 | 줄 넷 + "n개 더 보기 →" (그 묶음의 페이지로) |
| 하나도 안 걸림 | "질문으로 남겨 주세요" (`ask.html` 로) |

**전체가 아니라 묶음마다 넷으로 끊는 이유** — 전체를 하나로 자르면 앞 묶음(자료)이
자리를 다 먹어 뒤 묶음(개념·학습지)이 아예 안 보이는 일이 생긴다. 그러면 셋을 합친
의미가 없다. (`index.html` 의 `const 묶음최대 = 4`)

카드가 아니라 줄로 그리는 것도 홈 길이 때문이다 — 카드로 깔면 그것만으로 화면
하나를 넘긴다.

**개념은 자기 이름 말고 매달린 자료 제목으로도 걸린다.** "정사영"이라고 치면
그 자료뿐 아니라 그게 속한 개념(공간도형과 공간좌표)도 같이 나온다.

**자료가 아직 없는 개념도 검색된다.** 지금 `NODES` 19개 중 6개는 자료가 없는데,
그래도 "지수"를 치면 지수함수와 로그함수가 나오고 "자료 준비 중"이라고 알려 준다.
예전에는 아무것도 안 나왔다.

검색은 각 항목의 글자를 전부 이어 붙여 찾는다. 자료는
`title · subject · unit · desc · use · keywords · year`, 개념은 `name · subject ·
year · about · 매달린 자료 제목`, 파일은 `title · subject · kind · keywords · date`.
학생이 쓸 법한 말을 `keywords` 에 넣어 두면 잘 걸린다.
**목록에 한 줄 추가하는 것 말고는 손댈 것이 없다.**

빈 칸일 때 과목을 보여 주는 것은 장식이 아니다. 빈 검색칸만 놓아 두면 무엇을
칠 수 있는지 몰라 아무도 안 친다. 최소한 누를 것은 있어야 한다.

"자료 4개 · 개념 1개 찾았습니다" 줄(`.find-count`)은 **눈에는 안 보이고 화면낭독기만
읽는다.** 묶음 머리가 이미 같은 것을 보여 주므로 화면에 두면 같은 말이 두 번 나오고,
가운데 정렬이라 왼쪽 정렬인 묶음 머리와 부딪혀 보였다. `display:none` 으로 지우면
낭독기도 안 읽으므로 화면에서만 감춘다.

### 공지 — 접히는 한 줄

`index.html` 의 `<details class="notice-strip">`, **히어로 바로 아래**에 있다.
맨 위 한 개만 보이고 ＋ 를 누르면 나머지가 펼쳐진다. `NOTICES` 배열이 비면 줄 자체가
사라지므로 빈 게시판이 남지 않는다. 다른 페이지의 "공지" 메뉴(`index.html#notice`)로
들어오면 펼친 채로 뜬다.

### 자료실 — 내려받는 파일 (`files.html`)

`assets/files.js` 의 `FILES` 배열에 한 줄씩 적으면 목록이 된다 (올리는 법도 그 파일
맨 위에 적어 두었다). 배열이 비면 "아직 올린 파일이 없습니다" 한 줄만 나온다.
PDF 는 `files/` 폴더에 넣고, **파일 이름에 띄어쓰기를 쓰지 않는다**
(주소가 깨져 내려받기가 안 될 수 있다). `files/README.md` 도 참고 —
GitHub 에서 그 폴더를 열면 바로 보인다.

카드가 아니라 줄로 둔 이유: 파일은 그림으로 알아볼 것이 없다. 날짜 · 제목 ·
내려받기 세 칸이면 충분하고, 줄이면 열 개가 넘어가도 한 화면에 들어온다.

### 개념 지도 (`map.html`)

같은 자료 17개로 들어가는 **두 번째 입구**다. `library.html` 이 "무엇이 있나"라면
개념 지도는 "지금 배우는 게 어디서 왔나"에 답한다.

고칠 곳은 `assets/concepts.js` 세 군데뿐이다 (홈의 찾기도 이 파일을 읽는다):

- `NODES` — 개념 19개. 각 개념의 `demos` 배열에 자료를 한 줄씩 매단다.
  열쇠말(`trig`, `poly` …)이 곧 주소가 된다 → `map.html?n=trig`
- `LAYERS` — 배우는 순서대로 쌓은 층. 여기 적힌 순서가 화면 순서다
- `EDGES` — `[먼저, 나중]`. "이게 있어야 저게 된다"

**개념 상자의 좌표는 어디에도 적혀 있지 않다.** 배치는 CSS(flex)가 하고,
script 는 그려진 자리를 재서 선만 얹는다 — 그래서 폰이든 데스크톱이든
저절로 맞는다. 좌표를 손으로 박는 순간 좁은 화면에서 반드시 깨진다.

같은 줄에 나란히 놓인 두 개념(예: 평면벡터 → 공간도형)은 위아래로 이으면
선이 거꾸로 올라가므로, 옆으로 잇고 아래로 부풀린다.

`map.html?n=trig` 처럼 개념을 지정해 링크를 보낼 수 있다 (수업 중에 쓰기 좋다).

#### 개념을 골랐을 때 — 상자가 답한다

예전에는 **선만** 밝히고 상자는 그대로 두었다. 그러면 얇은 선을 눈으로 따라가야
답을 알 수 있었다. 지도가 하려는 말이 "이게 있어야 저게 된다"인데 그 답이 선
하나에만 실려 있던 셈이다. 지금은 상자 자체가 답한다.

| 표시 | 뜻 | CSS |
| --- | --- | --- |
| 검정 채움 | 고른 개념 | `.cmap-node.on` |
| 검은 테두리 | 먼저 알아야 하는 것 | `.cmap-node.pre` |
| 연두 채움 | 여기서 이어지는 것 | `.cmap-node.post` |
| 흐림 | 관계없음 | `.cmap.has-selection .cmap-node` |

테두리를 `border-width` 로 두껍게 하지 않고 `box-shadow: inset` 으로 그린다.
`box-sizing: border-box` 라 테두리가 굵어지면 안쪽 폭이 줄어 글자가 미세하게
움직이는데, 그림자는 자리를 안 먹으므로 상자가 흔들리지 않는다.

색이 세 가지면 읽는 법이 필요하다. 지도 위 `.cmap-legend` 가 그 역할을 하고,
**개념을 고르기 전에는 숨어 있다** — 아직 읽을 색이 없기 때문이다.

#### "여기까지 오는 길 전부 보기"

지도 위 스위치(`#cmapDeep`). 끄면 **한 단계**, 켜면 **거슬러 올라가는 사슬 전체**를
밝힌다. 학생이 실제로 하는 질문이 "미적분Ⅱ 하려면 뭘 알아야 해요"인데, 그 답은
한 단계가 아니라 사슬 전체이기 때문이다.

예를 들어 **적분법**을 고르면 — 끄면 앞이 2개(적분·미분법), 켜면 **8개**가 나온다:

> 다항식 → 함수와 그래프 → 지수함수와 로그함수 · 삼각함수 · 함수의 극한과 연속
> → 미분 · 적분 → 미분법

**나오는 순서가 곧 공부 순서다.** `앞전부()` 가 모은 것을 `LAYERS` 순서
(= 배우는 순서)로 정렬해 돌려주기 때문이다. 그래서 패널 제목에 "8개 · 배우는 순서"
라고 적어 둔다.

뒤쪽(이어지는 것)은 스위치와 상관없이 **늘 한 단계만** 보여 준다. 양쪽 다 전부
펼치면 가운데쯤 있는 개념에서는 거의 모든 상자가 켜져서 아무것도 구별되지 않는다.

`EDGES` 는 배우는 순서대로 난 길이라 되돌아오는 고리가 없다. 그래도 `앞전부()` 는
이미 담은 것을 건너뛰므로, 여러 갈래로 만나는 개념도 한 번만 나오고 실수로
고리를 만들어도 멈추지 않는 일은 없다.

### 제목 단계 (h1 → h2 → h3)

페이지마다 `h1`은 하나뿐이고, 그 아래로 단계를 건너뛰지 않는다. 검색 노출과
화면낭독기가 이걸 보고 페이지 제목을 잡으므로, 새 페이지를 만들 때도 지켜 주세요.

| 페이지 | h1 | h2 | h3 |
|---|---|---|---|
| `index.html` | 수학을 보다 (히어로) | 뭘 찾고 있나요 | — |
| `library.html` | 직접 보는 수학 | 과목 이름 (`.grid-head`) | 자료 카드 제목 |
| `map.html` | 개념 지도 | 층 이름 · 고른 개념 이름 | 먼저/이어지는/자료 |
| `files.html` | 자료실 | — | — |
| `ask.html` | 공부 방법, 편하게 물어보세요 | 받은 질문과 답 | 질문 한 건씩 |

푸터에는 제목이 없다. 예전에는 `Menu` 라는 `h3` 가 있었는데, 링크가 가로
한 줄이 되면서 이름표 없이도 무엇인지 보여서 뺐다 — 덕분에 단계를 신경 쓸
일도 없어졌다.

`library.html`의 과목 이름은 `render()` 안에서 `<h2>`로 만든다. 태그를 바꾸면
`style.css`의 `.grid-head h2` 선택자도 같이 고쳐야 글자 크기가 유지된다.

### 수업용 링크

자료를 열고 슬라이더를 원하는 값에 맞추면 **주소가 그 상태로 바뀝니다.**

demos/riemann.html?n=40&mode=right                직사각형 40개, 오른쪽 끝 값

주소에는 **기본값과 다른 것만** 담기므로 짧게 유지됩니다.

(몬티 홀처럼 슬라이더가 없는 자료에서는 버튼이 생기지 않습니다)

데모 한 개 = HTML 파일 한 개. 서로 영향을 주지 않으므로 마음 편히 추가·수정할 수 있다.

## 글 올리는 법

- **움직여 보는 자료** — `assets/demos.js` 의 `DEMOS` 배열 **맨 아래에** 추가합니다.
  비슷한 항목을 복사해서 고치면 됩니다. 홈의 찾기와 `library.html` 이 함께 봅니다.
  - `fig` : 카드와 검색 결과에 들어가는 작은 그림 (SVG)
  - `use` : 카드에 보이는 "이럴 때" 한 줄 — 수업에서 언제 꺼내 쓰는지
  - `desc` : 화면에는 안 나오지만 **검색에는 걸리는** 설명문 (`keywords` 와 같은 역할)
  - `d3: true` : 3D 자료에 붙는 검은 **3D** 배지
  - 과목 색과 목차는 `subject` 값을 보고 자동으로 붙습니다 (색은 `style.css` 의 `--sub-*`)
- **내려받는 파일** — `assets/files.js` 의 `FILES` 배열 (최신 글을 맨 앞에).
  PDF 는 `files/` 폴더에 (`files/README.md` 참고)
- **개념** — `assets/concepts.js` 의 `NODES`. 자료를 만들면 해당 개념의
  `demos` 배열에 한 줄 매답니다 (그래야 개념 지도에서도 그 자료로 갈 수 있습니다)
- **질문·답변** — `ask.html` 아래쪽 `QNA` 배열 (최신 글을 맨 앞에)
- **공지** — `index.html` 아래쪽 `NOTICES` 배열 (최신 글을 맨 앞에).
  홈에서는 맨 앞 한 개만 한 줄로 보이고 나머지는 ＋ 안에 접힙니다

한 줄 추가하고 파일을 올리면 화면에 그대로 반영된다.

과목이 하나 늘거나 이름이 바뀌면 `assets/demos.js` 의 `SUBJECTS` 만 고치면 된다.

과목 목록을 빼면서 그 부담이 없어졌다 — 아래 "푸터" 참고)

### 푸터

다섯 페이지 모두 같은 푸터를 쓴다. **딱 한 줄**이다 — 왼쪽에 이름, 오른쪽에
링크 다섯 개, 그 아래 쓰는 법 한 줄. 검은 색면(`--inverse-canvas`) 위에 흰 글씨다.

푸터는 '끝났다'는 표시지 두 번째 홈페이지가 아니다. 예전에는 과목 6개를 다시
나열하느라 홈 전체 높이의 31%(577px)를 차지했다. 지금은 데스크톱 **115px** 다.
링크를 다시 늘리고 싶어질 때 이 숫자를 기억해 두면 좋다.

**줄여 온 순서** — 한 번에 줄인 게 아니라 네 번에 걸쳐 줄였고, 매번 원인이
달랐다. 같은 실수를 반복하지 않으려고 적어 둔다.

1. **577px** — 3단(브랜드 / Menu / Contact). Contact 칸에 항목이 **하나뿐**이라
   오른쪽이 허전하게 비었다. 링크를 한 목록으로 합쳐 2단으로.
2. **380px** — 2단인데도 높았다. 링크 5개가 **세로로 쌓여** 오른쪽이 5줄인데
   왼쪽은 2줄에서 끝났다. 칸 높이는 둘 중 긴 쪽을 따라가므로 왼쪽 아래에 200px
   넘는 빈자리가 생긴 것. 링크를 가로 한 줄로 눕혀서 해결.
3. **250px** — 그러고 나니 왼쪽에 한 줄이 더 들어갈 자리가 생겨 자료 요약
   (`자료 17개 · 마지막 업데이트 …`)을 넣었다.
4. **115px** — 소개 문구와 자료 요약을 다시 뺐다. **자리가 남는다고 채운 것이
   문제였다.** 상단 바와 홈에 이미 있는 말이라, 여기서 또 하니 페이지가 두 번
   끝나는 것처럼 보였다. 남는 자리는 비워 두는 편이 낫다.

> 그때 같이 지운 것들 — `.footer-grid` / `.footer-desc` / `.footer-stat`,
> `assets/demos.js` 의 요약 줄 계산, `ask.html`·`map.html` 이 그 계산 때문에
> 읽던 `assets/demos.js`. 지금 그 파일을 읽는 것은 홈과 `library.html` 둘뿐이다.

**왜 검은 색면인가.** 흰 바탕에 실선 한 줄만 그어 두니 '아직 본문인가' 싶게
이어져 보였다. 색이 바뀌면 줄 하나 없이도 여기가 끝인 게 보여서, `border-top`
은 지웠다. 대신 어두운 바탕에서 안 보이게 되는 것 세 가지를 함께 뒤집어 뒀다.
이 셋은 색을 다시 바꿀 때도 같이 따라다녀야 한다.

| 원래 | 검은 바탕에서 생기는 문제 | 바꾼 것 |
| --- | --- | --- |
| `.caption` `rgba(0,0,0,.58)` | 검정 위 검정 — 안 보임 | `.footer .caption` 흰색 55% |
| `:focus-visible` 검정 테두리 | 키보드로 다닐 때 지금 어디인지 안 보임 | `.footer :focus-visible` 흰색 |
| `.to-top` 검은 원 단추 | 끝까지 내리면 배경에 묻힘 | 흰 테두리 2px (흰 바탕에서는 티가 안 남) |

**폰(390px)에서는** 이름과 링크가 각자 한 줄씩 되어 174px 이다. 가로 스크롤은
생기지 않는다. 메뉴를 더 늘리면 링크가 세 줄이 되니 그때 다시 잰다.

>   (필요한 열쇠는 처음 켤 때 서버가 만들어 저장소에 넣는다).
>   - 안드로이드·컴퓨터: 크롬·엣지·삼성 인터넷에서 바로 켜진다.
>   - 아이폰·아이패드: Safari 공유 단추 → **홈 화면에 추가** → 그 아이콘으로 열어서 켠다
>     (애플이 홈 화면에 올린 사이트에만 알림을 허락한다).
> - Formspree 메일은 예비로 남아 있다(`ask.html` 의 `폼주소`). 알림만 쓰려면 비워도 된다.

이 사이트는 서버 없이 파일만 올라가는 방식이라, **학생이 쓴 글을 사이트가 직접
저장할 수 없다.** 어딘가로 '보내는' 역할을 할 서비스가 하나는 필요하다.

**처음엔 구글 폼을 페이지 안에 심었었다.** 그런데 두 가지 문제가 있었다.
① 폼 안쪽(보라색 상단바, 구글 서체)은 남의 사이트라 이쪽에서 손댈 수 없어
사이트와 따로 놀았다. ② 사진 첨부 칸을 하나라도 넣으면 구글이 응답자에게
로그인을 강제해서, 응답에 학생 이메일이 남아 '익명'이 깨졌다.

**그래서 지금은 이 페이지 자신의 `<form>` 을 만들고, [Formspree](https://formspree.io)
(무료)가 그 내용을 선생님 이메일로 전달하기만 하는 방식으로 바꿨다.** 폼이 사이트
HTML 그 자체라 모양이 완전히 같고, 이름을 안 받으므로 진짜 익명이다. 학생 쪽에는
계정도 로그인도 없다 — 계정이 필요한 건 선생님(Formspree)뿐이다.

1. formspree.io 에서 계정을 만들고 New Form
2. 만들어진 Endpoint 주소를 복사 (`https://formspree.io/f/abcdwxyz` 모양)
3. `ask.html` 위쪽에 붙여 넣는다

```js
const 폼주소 = "https://formspree.io/f/abcdwxyz";
```

- `폼주소` 가 **비어 있으면** 칸이 잠기고 "질문 받는 곳을 준비하고 있습니다"
  한 줄만 나온다. 그래서 폼을 안 만든 상태로 둬도 페이지가 깨지지 않는다.
- 제출은 `fetch()` 로 처리한다. 성공하면 "질문이 전달됐습니다", 실패하면
  "지금은 안 보내져요"가 `.qform-status` 자리에 뜬다. 새로고침도, 페이지 이동도 없다.
- 이름 칸이 아예 없다 — Formspree 는 보낸 사람의 이메일을 요구하지 않는다.
  로그인도 없으니 학생이 누구인지 알 방법이 없다. 문제 사진처럼 계정이 꼭
  필요한 것을 받아야 한다면, 그때는 별도 페이지(구글 폼 링크 등)를 새로 만드는
  편이 이 폼의 익명성을 지키는 데 낫다.

답변은 Formspree 계정을 만들 때 쓴 이메일로 온다. 그중 공유할 만한 것을 `QNA`
배열에 옮겨 적으면 페이지 아래 "받은 질문과 답"에 쌓인다.

> **다른 방법도 있었다** — 카카오톡 오픈채팅(학생들이 이미 쓰는 앱이지만 밤에도
> 알림이 오고 질문이 흘러가 나중에 못 찾는다), Tally 같은 다른 폼 서비스(Formspree
> 보다 자체 UI가 있어 커스터마이징에 한계가 있다), 메일 주소만 걸어 두기(학생 폰에
> 메일 앱이 설정돼 있어야 열리고 주소가 공개돼 스팸이 온다). 사이트 안에 직접 만든
> 폼 쪽이 모양이 완전히 같고 진짜 익명이라 이걸 골랐다.

색을 바꾸고 싶으면 `assets/style.css` 맨 위 `:root` 의 값만 고치면 사이트 전체가 함께 바뀐다.

## 내 컴퓨터·폰에서 보기

**`폰으로 보기.bat` 을 더블클릭**하면 끝난다. 검은 창이 뜨면서 주소를 알려 준다.
그 창을 닫으면 서버가 꺼진다. (창은 켜 둔 채로 두면 된다)

- 이 컴퓨터에서는 `http://localhost:5173`
- 폰에서는 창에 찍히는 `http://192.168.…:5173` — **폰이 같은 와이파이에 있어야 한다**

폰용 주소는 공유기가 그때그때 정해 주므로 **켤 때마다 달라질 수 있다.** 외우지 말고
창에 찍히는 것을 그대로 보고 치면 된다 (`serve.js`가 매번 다시 찾아 준다).

3D 자료는 모듈을 불러오기 때문에, 파일을 그냥 더블클릭하는 방식(`file://`)으로는
열리지 않는다. 위 방법으로 열어야 하는 이유다.

명령창에 직접 치고 싶으면 이 폴더에서 `node serve.js`.

### 폰에서 안 열릴 때

1. 폰이 PC와 **같은 와이파이**인지 (폰의 데이터를 끄고 다시 해 보면 확실하다)
2. Windows 방화벽 창이 떴다면 '개인 네트워크'에 체크하고 [액세스 허용]
3. 그래도 안 되면 공유기의 '단말 간 차단(AP isolation)' 설정 때문일 수 있다 —
   이때는 아래 Vercel 로 올리는 편이 빠르다

## 새 자료 추가 순서

1. `demos/` 안에 새 HTML 파일을 만든다 (`projection.html`을 복사해서 시작하면 빠름,
   맨 아래 `<script src="../assets/state.js"></script>` 도 그대로 두면 수업용 링크가 함께 딸려 온다)
2. **`assets/demos.js`** 의 `DEMOS` 배열 **맨 아래**에 항목을 추가하고 `ready: true` 로 둔다
   (검색이 되도록 `keywords` 에 관련 용어를 넣어 둘 것)

그러면 이 셋이 저절로 따라온다:

- **`library.html`(직접 보는 수학)** — 과목별로 알아서 제자리에 들어간다.
  `SUBJECTS` 에 적은 과목 순서로 묶으므로, 배열의 어디에 넣든 상관없다.
  (예전에는 배열을 훑다가 과목이 바뀔 때마다 제목을 만들었다. 그래서 같은 과목을
  떨어뜨려 놓으면 제목이 두 번 생기고 같은 id 가 두 개가 되어 바로가기가 엉켰다.
  지금은 그 제약이 없다)
- **홈의 찾기** — 새 자료도 바로 검색된다. `keywords` 에 학생이 쓸 법한 말을
  넣어 둘수록 잘 걸린다
- **과목 칩의 개수** — 홈(빈 검색칸)과 `library.html` 위쪽 모두 배열을 세어 다시 붙인다

**한 가지는 저절로 안 된다** — 개념 지도에 매다는 것. `assets/concepts.js` 에서
해당 개념의 `demos` 배열에 `{ t: "제목", h: "demos/파일.html" }` 한 줄을 넣어야
개념 지도에서도 그 자료로 갈 수 있다. 이걸 빠뜨리면 자료는 잘 보이는데 개념 지도
쪽에서만 안 보이는, 알아채기 어려운 상태가 된다.

> `files.html`(자료실)은 `DEMOS` 와 **상관없다.** 그쪽은 내려받는 파일이라
> `assets/files.js` 의 `FILES` 라는 다른 배열을 쓴다.
